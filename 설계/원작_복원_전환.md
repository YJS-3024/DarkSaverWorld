## 최신 변경: 로그인·회원가입 로컬 서버 처리 (2026-10-27)

사용자가 로그인·회원가입 패킷을 로컬 ServerManager에서 처리하도록 명시적으로 요청했다. 이 범위는 앞선 인증 대체 구현 제거 이후 새로 허용된 기능이다.

- `ServerManager.BindLocalAccountService`가 로그인/가입/로그아웃/상태 요청 처리기를 소유한다. 클라이언트 UI는 요청을 보내고 응답으로 화면 상태를 바꾼다. 같은 매니저에 중복 등록하거나 다른 저장 경로로 바인딩하지 않는다.
- `CharacterServerBoundary`는 기존 `NativeAccountDirectory`/`NativeAccountStore`를 사용한다. 아이디 정규화·중복 거부, 암호 확인 및 PBKDF2-SHA256 저장을 수행한다. 같은 기기의 여러 계정을 지원하고 기존 계정/저장을 덮어쓰지 않는다.
- 로그인 실패/로그아웃은 이전 인증 ID와 슬롯 경로를 해제한다. 성공은 계정 ID와 분리 복사한 계정별 경로를 반환하며, 캐릭터 생성·초기금·튜토리얼·마지막 위치 자동 진입을 실행하지 않는다.
- 원본 로그인 화면의 가입 버튼→입력 폼→가입 요청→로그인 요청을 연결했다. 입력 폼은 이 로컬 가입 기능을 위한 것으로 원작 웹 가입 화면과 동일하다고 주장하지 않는다. 로그인 성공 후 원작 서버 선택 단계의 응답/화면은 여전히 별도 구현 대상이다.
- 로그인/가입은 현재 로컬 타입 계약이며, 원작 wire opcode·암호 전송 형태와 일치한다고 확정하지 않았다. `OriginalRestorationPolicy`나 삭제한 전투/캠페인 시뮬레이터를 재활성화하지 않는다.
- 신규 공유 인증 검사41건을 포함해 오프라인 통합4,405건 통과. ServerManager 응답/중복 바인딩/비활성 거부 및 UI 요청 흐름용 NUnit3개는 소스 컴파일만 확인했다. 실제 Unity Play/Test Runner 통과로 보고하지 않는다.

아래 삭제 표의 인증·가입 항목은 이전 단계의 기록이며 현재 실행 범위는 이 절을 우선한다.

### 사용자 승인 로컬서버 건물 왕복 연결

사용자 요청으로 카오시아 건물7곳(무기점·방어구점·장신구점·소모품점·은행·창고·신전)에 로컬 출입 프로토콜을 연결했다. 기존 외부 문/복귀 좌표와 원본 실내 리소스를 사용한다. 실내 도착은 Map.json의 진입 위치, 복귀 문은 하단 중앙(9.5,0.5)으로 로컬서버 콘텐츠에 명시했다. 이 좌표·왕복 연결은 원작 서버 패킷에서 확정된 값이 아니며, 사용자 승인 로컬 구현이다. 연결 근거가 없는2800 등 다른 실내나 필드·시나리오 문을 함께 활성화하지 않았다.

- `Resources/World/BuildingRoutes.json`: 14방향의 출발 지역/씬·문 위치·목적지/도착 좌표. 원본/로컬 보완 출처를 분리한다.
- `ServerManager.BindLocalBuildingTravelService`: MapEnterRequest, MapEnterCompleteRequest, 연결 지역의 WorldMoveRequest 처리기를 소유한다. WorldSceneCoordinator는 직접 승인 응답을 만들어내지 않는다.
- 서버는 캐릭터 진입 상태·현재 지역·문과의 거리·전투/튜토리얼/전환/입력 잠금·목적지 등록을 확인하고 Started/전환ID/정규 도착 좌표를 응답한다. 현재 입력에는 임의 도착 좌표를 받지 않는다.
- 클라이언트는 목적지 씬과 수신 좌표의 이동 가능 지형을 준비한 뒤 전환ID로 완료 요청한다. 서버 Ready 응답에서 위치·카메라를 적용하고 이전 씬을 해제한다. 실패/취소·오래된 완료·중복 진입은 거부하며 로딩 실패 시 기존 지역을 보존한다.
- 문까지 접근할 수 있도록 카오시아 및7개 연결 실내의 기본 이동만 같은ServerManager에서 단계 거리·지형 검증 후 응답한다. 기존 PlayerMoveSpeed를 재사용하며 원작 서버의 이동 판정 복원이라고 주장하지 않는다. 필드/시나리오 이동·상점 거래/시설 판정은 그대로 별도 경계다.
- 전환 중 검정 화면과 카메라 즉시 배치를 사용한다. 완료 후 기존 SaveWorld 요청으로 저장을 시도하며 저장 실패는 이동 실패와 구분해 LastTravelMessage에 남긴다.
- 소스/API 컴파일 오류0, 오프라인 통합5,605검사(건물 계약312검사 포함), 별도 리소스/연결/빌드 씬99검사 통과.16개 대상 씬이 빌드 목록에 등록돼 있음을 확인했다. 실제 Unity TestRunner/문 접촉/왕복/저장 재접속은 미실행이다.


### 실내 NPC·맵 원본 재확인

실내22개 원본MRC/GRS와 현재 리소스에 대한5,001검사가 통과했다(7,500지형칸·2,440장식 및 선택한 직원11명 원본 프레임). 이는 정적 리소스 보존 확인이며 실제 Unity나 원작 전체 NPC배치 검증이 아니다. 은행·창고의 현재 각1명은 원작 총인원 확정값이 아니고, 마법사의 집 상품표는 NPC 인원/좌표의 근거가 아니다. 현재직원은클라이언트JSON 배치이며 원작 서버가 보낸 개체 목록이 아니다. 자세한 사진 재대조와 기존Map.json npc필드 해석 주의점은 `분석/Saver_Late/screenshots/전체_스크린샷_분석대조.md` 최신 절, 수치 근거는 `Tools/MapChecks/original_interiors_check.json`을 따른다. 이번 확인으로 직원 수나 게임 규칙을 변경하지 않았다.
