# 원작 진입 UI·튜토리얼 재구현 (2026-10-31)

현재 구현 범위는 **시작/로그인 → 서버 선택 → 최초 지휘관 생성·저장 → 맵301 전투 튜토리얼 → 완료 기록 저장**이다. 새 `Assets/_Original` 코드이며 삭제한 `_Game` 실행기를 복구하거나 가져오지 않았다. 튜토리얼 완료 후는 `TutorialSceneRoot.WorldEntryReady` 통지 경계까지다. 마을·보상·일반 전투 규칙은 아직 연결하지 않았다.

## 사용 방법

1. Unity6000.5.7f1에서 `Assets/_Original/Scenes/Start.unity`를 연다. 시작 씬에 `Original Entry`의 `EntrySceneRoot`·`LocalServerManager`와 `NativeEntryArt` 참조가 연결되어 있다.
2. **DarkSaver → 로컬 서버 → 계정 관리**에서 검증 계정을 등록한다. 이는 서버 운영용 에디터 창이며 게임 안의 원작 가입 화면이 아니다. 이전 계정/저장 파일을 가져오지 않는다.
3. Play하면 Logo6 배경과 로그인 패널이 바로 표시된다. 별도의 새 시작 버튼·자동 로그인·익명 진입은 없다.
4. ID/암호 입력 → 접속 → 로컬 서버 확인/선택 → 접속. 빈 계정은 바로 파이터/나이트/매지션 생성창으로 진행한다. 10슬롯 선택 UI를 거치지 않는다.
5. 카드 선택 → 이름 입력 → 확인. 저장 성공 후 생성창을 닫고 CharacterReady를 전달한다. 실패하면 완료 처리하지 않는다. 완료하지 않은 캐릭터는 원문 튜토리얼301을 시작한다.
6. 다시 Play/로그인/서버 선택하면 저장된 이름·직업·식별자·튜토리얼 완료 여부를 반환한다. 최초 생성창을 다시 띄우거나 기존 캐릭터를 덮어쓰지 않는다.

UI는 Play 때 Unity UI Canvas로 한 번 구성한다. UI Toolkit이나 UI 전용 카메라는 사용하지 않는다. Canvas는 ScreenSpaceOverlay, 논리640×480, 종횡비를 유지하며 남는 화면은 검정 여백이다. 이름/암호 입력과 버튼은 실제 uGUI InputField/Button이다.

## 로컬 서버 경계

`EntryClient → EntryRequest → LocalServerManager → EntryAccountService/파일 저장 → EntryReply → 화면 갱신`으로 처리한다. 매니저의 ResponseReceived도 응답을 전달한다. 통신은 프로세스 안의 명시적 계약이며 원작 wire opcode·패킹·전체 송신 순서를 복원했다고 표시하지 않는다. 소스에서 관측한 서버 선택 요청0x800C도 이 로컬 계약의 opcode로 임의 배정하지 않는다.

서버가 인증·서버 선택·첫 생성 순서를 검사한다. 잘못된 비밀번호/서버/직업/입력과 중복 생성을 거부한다. 생성은 저장 성공 후에만 공개하며 실패 시 이전 계정/캐릭터를 유지한다. 다른 계정과 응답 스냅샷은 분리한다. 계정 파일 손상/미지원 버전을 빈 계정으로 덮어쓰지 않는다.

다음은 **새 로컬 호스팅 정책**이며 원작 사실이 아니다.

- 서버1개(ID1·로컬 서버), 계정 ID는 대소문자를 구분한다.
- 비밀번호는 계정별 salt16바이트·PBKDF2-SHA256100000회·hash32바이트로 저장한다.
- 로컬 입력은 비어 있지 않은 올바른 Unicode·128코드유닛 이내·제어문자 제외로 제한한다. 원작 이름/ID 길이·금칙어·중복 이름 정책으로 일반화하지 않는다.
- JSON v1 한도1MiB, 임시 파일 후 원자 교체. 신규 경로는 `Application.persistentDataPath/OriginalLocalServer/accounts-v1.json`이다.
- 최초 캐릭터는 로컬 식별자·이름·직업만 보관한다. 식별자 GUID는 로컬 저장 식별자이며 원작 유닛 번호가 아니다. HP/MP/골드/장비/기술/위치/완료 상태를 추측해 지급하지 않는다.

## 검증 결과

- 새 Runtime9개·Editor2개 API 보조 컴파일, 별도 Player 조건 컴파일 모두 오류0·경고0.
- 관리형 **82항목 통과**. 세 직업의 실제 임시 JSON 파일 저장/재연결3회, 인증·순서/잘못된 서버·생성 거부, 저장 실패 보존, 중복 생성 방지, 다른 계정 보존, 손상/미지원 저장 거부, 이전 저장 sentinel 보존, Unicode/잘못된 파일 경로 거부를 포함한다.
- 원본 x86 명령/상수8개 직접 대조, 시작 씬의 스크립트2개·아트 GUID 참조와 파생 그림6개 해시 확인.
- `check_foundation.py`는 원본2519출력의 출처 대조를 유지하고 새 진입 기능을 명시적 허용 목록으로 구분한다. 새 원본 근거 없이 이전 게임 코드/리소스를 다시 포함하지 않는다.
- 실제 Unity 실행 시도는 **종료코드198, 활성 Editor 라이선스 없음**으로 종료했다. 로컬 IPC 접근 후 라이선스 초기화까지 확인했으나 임포트/Play/키보드·마우스/렌더링은 통과 처리하지 않는다.

`Tools/OriginalEntryChecks/entry-check.json`과 `unity-attempt.json`을 구분해 읽는다. API/관리형 통과를 Unity Play 결과로 바꾸지 않는다.

## 실제 Unity에서 확인할 항목

아래 항목은 아직 미실행이다.

1. 임포트·컴파일·Start 씬의 Missing Script/참조와 Console 오류, UI 카메라 경고가 없는지.
2. 640×480 및 넓은 화면에서 시작/로그인 위치·여백, ID/암호 클릭 위치·글자 중심·마스킹·Tab/Enter.
3. 잘못된 암호의 원본 안내 그림·확인 클릭/Enter, 가입/옵션 미지원 안내와 입력 차단/복구.
4. 서버창277,276·로컬 한 행·기본 첫 행 선택·hover/pressed·접속/나가기. 로그인 전 직접 요청은 거부되는지.
5. 세 별도 계정으로 100/101/103 카드·62×62 초상·이름·확인, 생성창 좌표와 종횡비·겹침.
6. 생성 완료 통지가 한 번 전달되고 후속 마을/튜토리얼을 임의 로드하지 않는지.
7. Play 종료→로그인→서버 선택 후 식별자/이름/직업 복원, 중복 생성 방지·다른 계정 보존.
8. 실제 Player 빌드·파일 권한 오류·재시작. 기존 실패 저장/계정과 분리해서 검증한다.

원작 GDI 굴림12/폭5/굵기600과 Unity OS폰트의 픽셀 일치는 미확정이다. 설치된 굴림을 우선하고 대체 OS폰트를 사용할 수 있다. 구름 안내의 전체 화면상 위치는 이번 Unity 표시 배치이며 원작 전역 좌표를 확보했다고 주장하지 않는다. 원본 실행/녹화와 전체 마우스 포인터·개별 능력 바 도움말의 동작까지 동일 검증을 마친 상태는 아니다.


## 새 튜토리얼301 연결

`Runtime/Tutorial`은 원문 실행기·임시 유닛·로컬 요청/응답·Unity UI 표시로 구성한다. `EntrySceneRoot.CharacterReady`를 같은 시작 씬의 `TutorialSceneRoot`가 받고, `LocalServerManager.Request_BeginTutorial`이 인증/서버 선택/캐릭터를 확인한 뒤 실행기를 만든다. 입력은 `Request_TutorialInput`, 완료는 `Request_CompleteTutorial`, 응답 통지는 `Notify_Tutorial`이다. 원작 wire opcode/패킹을 새로 확정했다는 뜻은 아니다.

### 명령 판정에서 주의할 점

`CHARDIR`·`CHARSETSKILL`·`SETHP`·`SETMP`·`WAITFORMOVEEND`는 원작 GameCtl의 전용 분기가 없으므로 별칭으로 실행하지 않는다. **그렇다고 튜토리얼 기술10101 자체가 없다는 뜻은 아니다.** UserUnit `dmSetAbility`0x1000EA34..EA6B가 원문 CHARABILITY 호출4개에 임시 마법101/기술10101도 설정한다. 실제 PE 명령 바이트를 다시 대조해 이 후속 동작을 반영했다. CHARABILITY 없는 후속201/805에 이 부여를 확장하지 않는다. HPSET은50/95/0/99의절대값이며 비율·완전회복으로 바꾸지 않는다. SETMP 오표기를 소비MP 계산의 근거로 사용하지 않는다.

MESSAGE mode1의 원본 시작점은40,50이다. GameCtl0x10008A17..8A43의 좌표/크기와0x10008B89..8BF6의64픽셀 초상·세 줄/20픽셀 간격을 확인했다. 원문 ASCII 양끝 공백은 화면 문자열에서만 제거하고 원본 파일을 수정하지 않는다.

### 완료·재시작·저장

- 신규 생성 직후 또는 미완료 캐릭터 재접속이면 명령1부터 실행한다. 중도 종료 커서·임시 HP/MP·유닛·효과를 저장하지 않는다. 원작 서버의 재개 정책을 복구했다는 주장이 아닌 사용자가 확정한 재시작 정책이다.
- ENDGAME만으로 완료하지 않는다. END까지 도달한 서버 실행기만 완료 저장을 허용한다. 완료 요청으로 수업을 건너뛸 수 없다.
- `accounts-v1.json` 캐릭터에 선택 필드 `tutorialCompleted`를 추가했다. 필드 없는 새 기반 계정 파일은 미완료로 읽는다. 다른 구버전 싱글판 저장은 불러오지 않는다.
- 저장 실패면 완료 표시를 쓰지 않고 재시도한다. 성공 후 중복 완료 호출은 다시 쓰지 않는다. 새로 등록된 다른 계정도 보존한다.
- 완료 후 다음 맵 진입 이벤트만 통지한다. 현재 마을 구현이 없어 마지막 화면에 머문다. 재접속 시 완료 캐릭터는 튜토리얼을 반복하지 않고 같은 다음 맵 경계로 전달된다. 초기 자금·반지·마을 좌표를 임의 부여하지 않는다.

### 표시 변환의 한계

CRT clock을 Unity의 비배율 밀리초로 대응하고 이동80ms/4단계,공격·사망20ms,마법40ms,대기 프레임125ms를 표시용 상수로 분리했다. 이는 원작 장치에서 실측한 속도가 아니다. AP 일반 최대/자연 회복/행동 소모는 만들지 않았다. CHARMENU 시연 게이지는 대본의2/3/4/5를 가장 큰 시연값으로 표시 정규화하고99는 가득 참으로 표시한다. 이 표시 배율을 원작 AP최대5로 사용하지 않는다. 원작 미확정 AP20/초당2 정책도 이식하지 않았다.

굴림 우선 OS폰트의 래스터 출력, 프레임 간격·보간과 사운드 장치의 정확한 일치는 실제 원작 재생으로 검증하지 않았다. MIDI 음색은 FluidSynth/TimGM6mb이며 원작 Windows 녹음이 아니다. 창 닫기/최소화의 첫 요청 억제와 필수 동맹 체크 보존은 구현되어 있지만 모든 콜백/픽셀 경계의 실행 동일성을 주장하지 않는다. 제공된 최소화 원문은0/3/24만 사용하며1의 부재 그림을 새로 그리지 않는다.

## 새 튜토리얼 검증 결과와 직접 검증 순서

현재 `Tools/OriginalTutorialChecks/check_tutorial.py`는 생산 실행기·계정·파일 저장 코드로99개 계약 검사,3직업을 포함한 전체 진행5회,입력480회·142개 대기 위치를 검증한다. 프레임 반복을 별도 테스트 수로 세지 않는다. 기존 진입82개 계약,Runtime/Editor/Player API 컴파일 오류0/경고0,새 PE 명령10곳·파생 출력66개와 씬 참조 검사를 통과했다. 삭제 이전 테스트 결과는 합산하지 않는다.

실제 Unity 실행은 앞선 동일 환경 시도에서 라이선스 없음(종료198)으로 차단됐다. 이번 관리형/보조 컴파일 검사를 Unity 임포트·Play·청음·물리 입력 통과로 취급하지 않는다. 직접 검증은 별도 계정과 저장 경로에서 다음 순서로 진행한다.

1. Start씬 Play→등록 계정 로그인→로컬 서버 선택→세 최초 직업 각각 생성→301 첫 대사/네 유닛 확인. 별도 대기실/10슬롯 선택/임의 선행 대사가 나타나면 실패.
2. 처음부터 마우스/지정 F키만 사용해 마지막 “행운을 비네.”까지 진행. 대사/타이머·입력 한 번으로 여러 단계가 건너뛰지 않는지 확인. 잘못된 대상/타일/F키가 대기를 해제하면 실패.
3. 이동/공격/마법 아이콘을 누른 뒤에만 각각의 원본 범위가 표시되는지, 이동 안내는4,7→2,7→4,7인지, 오른쪽 이동 후 아래를 향하지 않는지 확인.
4. 대기 중 캐릭터/몬스터 애니메이션,특수기V/옵션 컴퓨터,고정 회색 마스크,상태창 앞의 캐릭터 상대 메뉴,늘어나지 않은32×32 상태 몸체를 확인.
5. F2 상태 수치와 HPSET50/95/0/99,마법101/대상410,용병001/002의3행동·직접 명령/자동 방어·실제 이동/제거를 확인. 실제 일반 전투 피해/소비MP 공식 검사와 구분.
6. F1~F12 안내,승리조건 원문,지휘관 한 행,미니맵,마우스 지형 미리보기,동맹 ‘나’/‘사부’·노란 체크·교관 보라/파랑 변경을 확인. 체크 hover가 옆 그림을 노출하면 실패. F7 창은 원작 GameCtl 기준으로 새로 나타나지 않음.
7. 별도 계정의 튜토리얼 중간에 Play 종료→재시작/로그인/서버 선택. 처음 네 유닛과 첫 대사로 돌아오는지 확인. 끝까지 완료한 계정은 완료 플래그 저장·재접속 후 재수업 생략을 확인. 마을 이동은 아직 검증 대상 아님.
8. 저장 실패는 별도 fixture로 재시도·상태 보존을 확인. 원래 계정/실패 저장은 덮어쓰지 않는다. 음향 청음·실제 화면 겹침·OS 입력은 검사 기록을 남긴 경우만 통과로 기록.

현재 재현 도구는 `Tools/OriginalTutorialChecks/{build_tutorial_assets.py,check_tutorial.py,tutorial-assets.json,tutorial-check.json}`이다. `SourceIndex.json` 원본 목록과 새 파생/실행용 목록을 섞지 않으며 `Tools/OriginalRestart/check_foundation.py`의 원본·백업 대조를 유지한다.
