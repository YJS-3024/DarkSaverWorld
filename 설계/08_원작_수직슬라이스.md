# 원작 재현 수직 슬라이스

> 현재 데이터 분석 기준은 후기 설치본이다. [후기 버전 분석 기준](11_후기버전_분석기준.md)을 우선한다. 이 문서의 과거 파일·코드 주소·검증 기록은 당시 버전에 한정되며 변경된 후기 실행 파일에 자동 적용하지 않는다.


## 목표

첫 재현 구간은 `엔트리아 필드 → 심벌 조우 → 전술 전투 → 보상 후 필드 복귀`로 한다.
게임 규칙과 화면 밀도는 원작을 우선하고, 해상도 대응과 입력 보조만 현대화한다.

## 확인된 기준

- 원작 화면 자료는 약 640×480이며 필드와 전투 HUD가 화면에 함께 배치된다.
- 맵 기본 타일은 32×32 픽셀이다.
- 보병과 일반 몬스터 시트도 32×32 셀 단위로 사용할 수 있다.
- UI는 갈색 석재·금속 테두리 패널과 푸른 슬롯 선이 핵심 시각 요소다.
- 전투는 다수 유닛, AP, 일반 공격, 직업 기술, 마법, 아이템, 휴식을 유지한다.

## 이번 적용

- `mdsr0` 잔디 타일을 엔트리아 필드 바닥에 적용한다.
- 보병 시트를 플레이어와 아군 토큰에 적용한다.
- 일반 몬스터 시트를 필드 심벌과 적 토큰에 적용한다.
- 원본 MRC/ARC/ATR 등은 분석 자료로만 보존하고 `Assets/`에는 복사하지 않는다.
- 에디터에서 원본을 분석·변환한 뒤 Unity 타일·스프라이트·씬·설정 에셋으로 재구성한다. 빌드와 플레이 중에는 원본 파일 경로를 참조하지 않는다.

## 플랫폼 대응

- 원작과 같은 640×480 논리 좌표를 유지하고 실제 화면에는 종횡비를 보존해 확대한다.
- Windows는 창 크기와 전체 화면 모두 레터박스로 대응하며 키보드·마우스를 지원한다.
- 모바일은 노치와 시스템 영역을 제외한 Safe Area 안에 배치하고 필드 터치 이동을 지원한다.
- 기본 방향은 가로 화면이며 세로 화면에서도 잘리지 않고 레터박스로 표시한다.
- 전투 명령은 모바일 터치를 고려해 최소 36 논리 픽셀 높이로 배치한다.

### 2026-10-16 논리 화면 적용

- `GameConstants.ReferenceScreenWidth/Height`를 640×480으로 두고, `Rendering/GameScreen`에서 비율 유지 표시 영역·화면/논리 좌표 변환을 공통 처리한다. 640×480은 화면 자료 기반 복원 기준이며 실행 파일의 지원 해상도 목록을 확정한 값은 아니다.
- UI Toolkit은 640×480 논리 컨테이너를 표시 영역에 맞춰 동일 비율로 확대한다. 시작·마을·카탈로그·부대 편성·전투 UI가 같은 좌표계를 사용한다. 별도 UI마다 실제 해상도로 다시 확대하지 않는다.
- 메인 카메라의 표시 영역도 4:3으로 맞추고 남는 공간을 검게 표시한다. 최초에는 사용자 지정 크기6을 유지했으나, 2026-10-17 사용자 승인으로7.5로 조정했다. 480/(2×32PPU)=7.5이므로 32픽셀 캐릭터·타일과 32픽셀 UI 셀의 화면 배율이 일치한다. 원본 실행 파일의 카메라 상수로 확정한 값이 아니라 Unity 픽셀 배율 보정값이다. UI 레이아웃·이동 속도·전투 수치는 유지한다. 여백에서 시작한 마우스 이동/전투 명령은 차단한다.
- 7.5 배율 검증: 카메라 투영으로 기준640×480에서1월드 유닛=32화면 픽셀 검사 및 기존 좌표 변환 검사 통과. `Play-20261017-170448/battle-menu-0.png`에서 캐릭터/UI 비율 확인. 실제795×596 플레이에서 월드 셀/UI32셀 모두39.733화면 픽셀로 일치했고 이동1·공격2·휴식3→패배 결과 승인·월드 복귀 통과. 명령 API 검사이며 실제 마우스 장치 이동 테스트는 아니다. 컴파일·Unity 콘솔 오류0. 검증용 카메라도 하드코딩6 대신 공통 상수를 사용한다.
- 월드 좌표의 이름·피해 숫자는 화면 좌표를 논리 좌표로 바꾼 뒤 그리며, UI 클릭 차단은 실제 마우스 좌표를 동일하게 역변환한다. 지도 레이캐스트는 4:3 카메라의 실제 화면 좌표를 그대로 사용한다.
- 전투 패널 폭을 줄이고 초상화를 재정렬해 논리 화면 안의 메뉴 공간을 확보했다. 이 배치는 원본 UI 픽셀 좌표 확정이 아닌 해상도 전환에 필요한 배치 보정이다. 모바일 Safe Area·최소 터치 크기와 정수 배율 픽셀 퍼펙트 처리는 별도 남은 항목이다.
- 검증: 관련 직접 호출 검사63건 통과(4:3·16:9·세로·소형 화면 비율 계산4건 포함, Test Runner 전체 실행 아님). 기존 아군 목록 검사의 공격 선택 준비에 최대 AP와 명시적 임시 비용 프로필을 적용한 뒤 준비값을 복원했으며, 화면 밖 포인터는 차단하도록 기대값을 갱신했다. 게임 AP/비용 규칙은 변경하지 않았다. 실제 Play는 `Tools/CombatRulesChecks/Play-20261016-230009/`에 캡처·기록을 보관했다. 이동1·공격2·휴식3→패배→Battle 언로드→맵 입력 복구를 확인했다. 실제 캡처는 약795×596의 4:3 Game View이며, 와이드/세로의 실제 UI 화면 캡처 및 실제 마우스 자동 클릭까지 검증한 것은 아니다. 런타임 컴파일 오류0·Unity 콘솔 오류0.
- Full HD 후속 확인: `Play-20261016-230900/`에서 1920×1080 실제 캡처를 확인했다. 중앙1440×1080·좌우240픽셀 여백, 카메라4:3·크기6을 기록했고 여백 포인터가 맵 입력으로 통과하지 않는지 실제 플레이 코드로 확인했다. 이동1·공격2·휴식3 후 패배 결과 확인·맵 입력 복구가 통과했으며 기존 Game View 프리셋8과 깨끗한 `World1010_Map` 씬으로 복구했다. 임시 프리셋을 추가하거나 사용자 세이브를 덮어쓰지 않았다. 아군 목록은 작은 글자·한 줄·잘림표로 표시하고 전체 역할/이름/AP는 툴팁에 유지한다. 전투 메시지도 한 줄·툴팁으로 처리해 복귀 버튼 쪽으로 줄바꿈되지 않게 했다. 해당 UI 재사용 검사와 컴파일이 통과했다. 이 기록으로 와이드 실제 화면 확인 보류를 해소한다. 세로 실제 캡처·실제 마우스 자동 클릭·원본 UI 전체 픽셀 일치는 여전히 미검증이다.

## 보병 시트 기준

- `1.BoByeong.png`는 12×8개의 32×32 셀로 사용한다.
- 한 캐릭터는 가로 3프레임×세로 4방향을 차지한다. 한 시트에는 가로 4명×세로 2명, 총 8개 슬롯이 있으며 슬롯 번호는 왼쪽 위부터 행 우선이다.
- 대응 원본 `char0/100r.bmp`의 상단 4행은 현재 Unity 추출 이미지 이름 기준 `Up·Down·Left·Right`에 각각 정확히 일치한다. 다만 원본 코드의 실제 화면 이동 방향 기준 행 순서는 **위·아래·오른쪽·왼쪽**이다. 현재 런타임의 좌우 배열 교환은 이 차이를 보정한다.
- Unity 일반 직업은 정지와 이동 모두 공유 시계 기반 왕복 프레임을 사용한다. 간격은 `GameConstants`에서 각각 조정한다.
- 확인한 제공 리소스의 보병 7단계 BMP는 3×6셀(96×192)이며, 합성 직업 시트에는 상단 4행만 들어 있다. 하단 2행의 동작 의미는 아직 확정하지 않는다.

### 제공 리소스와 설치본 추출 이미지의 차이

- `Compare-JobSheetSlots.ps1`은 96×128 영역의 모든 픽셀을 RGB로 정규화한 뒤 SHA-256을 비교한다. 투명 픽셀과 원본 색상 키인 검정을 같은 배경으로 취급한다. 이전 표본 비교 결과를 전 픽셀 검사로 보강했다.
- 제공 리소스의 후보 BMP 95개와 시트 80개 슬롯을 비교하면 71개 슬롯이 일치한다. 일반 직업 64개, 빈칸 6개, 기병 슬롯 7의 898 그림이다. 결과: `분석/Saver_1.2/catalogs/job_sheet_reference_matches.csv`.
- 설치본의 `decoded/all_arc/gameres`에서 크기 조건을 만족하는 BMP 321개와 비교하면 일치 슬롯은 30개다. 일반 직업 64개의 같은 이름 파일은 모두 존재하지만, 제공 리소스와 파일 자체가 같은 것은 24개이고 나머지 40개는 상단 방향 프레임도 다르다. 변경 이유나 제작 시점은 확인되지 않았으므로 버전 관계를 단정하지 않는다. 결과: `분석/Saver_1.2/catalogs/job_sheet_slot_matches.csv`.
- 재현 도구: `분석/Saver_1.2/tools/Compare-JobSheetSlots.ps1`. `SheetRoot`, `SourceRoot`, `OutputPath`를 지정한다. 이 비교는 이미지 배치만 검증하며 BMP 하단 두 행의 동작 의미는 증명하지 않는다.

### 캐릭터 렌더링 코드 확인

설치본 `userunit.dll`의 정적 역어셈블 결과다. 아래 주소는 해당 DLL의 VA이며, 원본 프로그램은 실행하지 않았다. 재현 도구는 `분석/Saver_1.2/tools/Inspect-SaverFunction.py`이다(`pefile`, `capstone` 필요).

| 방향 값 (`+0x148`) | 화면 이동 | BMP 행 / Y |
| --- | --- | --- |
| 1, 5, 6 | 왼쪽, 왼쪽 위, 왼쪽 아래 | 3 / 96 |
| 2, 7, 8 | 오른쪽, 오른쪽 위, 오른쪽 아래 | 2 / 64 |
| 3 | 위 | 0 / 0 |
| 4 | 아래 | 1 / 32 |

- 방향 선택: `0x1000B9EA–0x1000BA43`. 실제 이동 오프셋: `0x1000BDF8–0x1000BF57`. 대각선 이동도 가능하지만 그림은 좌우 방향을 사용한다. 여기서 오프셋 계수는 직선 8, 대각선 5이며, 이를 Unity 월드 속도로 직접 환산하지 않는다.
- 일반 직업 프레임 함수 `0x1000AC70`은 `(GetTickCount / 간격) & 3`의 결과 3을 1로 치환한다. 따라서 순서는 `0→1→2→1`이며 개별 캐릭터가 아닌 전역 시계 기준이다. 기본 표시 호출은 333ms(`0x1000BA43`), 이동 표시는 125ms(`0x1000BD9E`) 간격이다. 특수 ID 980–998은 별도 분기를 사용하므로 이 규칙을 모든 이미지에 일반화하지 않는다.
- 이미지 로더 `0x1000ADA0`은 읽은 BMP의 실제 크기로 표면을 만들고 전체 이미지를 복사한다. 하단 두 행을 위쪽으로 재배치하는 변환은 이 경로에서 확인되지 않았다.
- 공격 시작 `AttackChar`(`0x1000CEE0`)는 상태 비트 `0x4`, 방향, 대상 및 표시 오프셋을 설정한다. 본체 표시 후 공격 효과를 다른 이미지 표면에서 덧그리는 경로(`0x1000FF1C` 이후)가 확인된다. 이것만으로 BMP 하단 두 행을 공격 프레임이라고 판단할 수 없다.
- 사망 설정 `dmKillChar2`(`0x1000F030`)의 상태 비트 `0x80`과 시체 표시 경로(`0x1000FCDE` 이후)도 확인했다. 확인한 시체 본체 프레임은 상단 네 행을 선택하며, 별도 효과가 추가된다.
- 캐릭터 이미지 테이블 `0x100DF40C`의 직접 주소 참조를 추가 점검했다. 추가 참조 `0x1000E890`은 해제, `0x100111F0`은 초기화 경로였다. 확인한 기본·이동·공격·시체 경로에서는 Y=128/160의 하단 두 행 사용을 찾지 못했다. 간접 참조나 다른 모듈까지 배제한 것은 아니므로 **미사용 확정이 아니라 용도 미확정**으로 남긴다.

Unity 적용: `DirectionalSpriteAnimator`의 3프레임 재생을 `0→1→2→1`로 변경하고 정지 333ms·이동 125ms를 `GameConstants`로 분리했다. 대각선은 좌우 그림을 사용한다. 공유 시계는 Unity 실행 경과 시간이며 원본 Windows 전역 시계와 시작 위상까지 일치시키지는 않는다. 특수 ID 980–998의 별도 재생 분기는 아직 구현하지 않았다.

## 저장

- Windows와 모바일 모두 `Application.persistentDataPath`에 JSON 형식으로 저장한다.
- 필드 위치, 토벌 진행도, 소지금, 물약 수량과 파티 성장 상태를 보존한다.
- 전투 승리 후 필드 복귀 시 자동 저장하며 필드 HUD에서도 수동 저장할 수 있다.
- 저장 데이터에는 버전을 기록해 이후 데이터 구조 변경을 판별한다.

## 아이템 시트 기준

- `Items/Item.png`는 100×10개의 32×32 셀로 사용한다.
- 현재 회복 물약은 첫 행의 87번 열을 사용하며 전투 명령에 원작 아이콘을 표시한다.
- 다른 장비와 소비 아이템은 명칭을 검증한 뒤 동일한 인덱스 방식으로 추가한다.
- 필드 HUD에서 원작 인벤토리 창을 열어 파티원을 선택하고 회복 물약을 사용할 수 있다.
- 장비 탭에서 용병검과 가죽갑옷을 파티원에게 장착·이전·해제할 수 있다.
- 장비 보너스는 기본 성장 능력치와 분리하며 실제 전투 피해와 방어 계산에 반영한다.

## NPC와 상점

- 엔트리아 필드에 상인 NPC를 배치하고 접촉 시 자동 이동을 중지한다.
- 대화창에서 현재 물약 수량과 소지금을 확인하고 회복 물약을 구매할 수 있다.
- 물약 가격과 구매 판정은 UI와 분리된 규칙으로 관리한다.

## 퀘스트 목표

- 의뢰는 몬스터 처치 수, 지정 위치 아이템 획득, 확률 드랍 아이템 납품을 함께 지원한다.
- 엔트리아 상인 의뢰는 마물 2회 처치, 황야 약초 1개, 마력 결정 1개를 요구한다.
- 마력 결정은 전투 승리 시 40% 확률로 획득하며 모든 조건을 충족해야 납품할 수 있다.
- 목표별 진행도와 납품 완료 여부는 저장 데이터에 포함한다.

## 보병 통행 속성 검증

- 원본 `TileAttr.csv`에서 이동값 `99`인 속성은 보병 통행 불가다. 물 속성 `6`도 보병은 `99`이므로, 물 잠김 렌더 효과가 존재한다고 해서 보병이 물을 통과할 수 있는 것은 아니다.
- 원본 `1000.mrc`의 차단 칸은 속성 `9` 536칸, `1010.mrc`는 `3·6·9` 합계 16,662칸, `01.mrc`는 `3·6·9·24` 합계 850칸이다. 생성된 세 Unity 씬의 차단 타일 수와 각각 일치한다.
- 이 판정은 현재 보병 플레이어에 한정한다. 다른 병종의 이동값은 별도로 적용해야 하며, 물 잠김 오버레이는 실제로 물 타일에 진입할 수 있는 유닛에 사용한다.
