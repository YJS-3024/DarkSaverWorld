# 원작 F4 더블클릭 재확인 (2026-10-30)

사용자 기억인 ‘소지품/장비 더블클릭으로 장착·해제’가 확보한 클라이언트에 있는지 구형·후기를 정적으로 조사했다. 게임 코드는 변경하지 않았다.

## 결과

확보한 두 실행 파일에서는 드래그 경로가 확인되지만, 장비 더블클릭 장착·해제 경로는 확인되지 않았다. 다른 서비스 시점의 클라이언트까지 해당 기능이 없다고 단정하지 않는다.

후기 파일은 saver/data1.cab에서 Saver.exe 한 파일만 /tmp에 추출했다. SHA256 dd512172256cf4795717aed156746fe6588b3434ed1e249ae59146e63d6e4689가 기존 후기 분석과 일치한다. 설치·실행하지 않았다.

- 구형 장비창 vtable0x447C84의 포인터 누름0x41F910/놓음0x41FAE0에서 소지품28칸·장비7칸 히트 검사 및 장착/해제40송신0x420800으로 이어진다. 같은 장비 칸에 다시 놓는 경로0x41FDDA는 출발/도착이 같으면 송신을 건너뛴다.
- 후기 장비창 vtable0x486108을 점프 thunk까지 풀어 누름0x46A7D0/놓음0x46AA20/송신0x46BAE0을 확인했다. 확인한 송신 호출은 놓음 처리와 별도 드롭 경로에 있다.
- 공통 입력에는250ms 이내의 연속 입력 검사(후기0x433D51)가 있다. 따라서 원작 전체에 더블클릭 처리가 없다고 해석하면 잘못이다. 해당 분기의 vtable+0x48은 장비창 전용 함수가 아니라 상속한 공통 창 처리0x4344B0으로 간다. 창 내부 상태+0x80을 검사하며 확인 범위에서 장비 슬롯 판정/40송신으로 연결되지 않았다. 단순히 더블클릭 타이머가 있다는 이유로 자동 장착이라고 이름 붙이지 않는다.

원작 동일 기준을 유지하기 위해 현재 Unity F4에 더블클릭 장착/해제를 추가하지 않았다. 이 조사만으로 사용자의 다른 시점 기억이 틀렸다고 판단하지 않는다. 실제 원작/Unity 실행 검증은 하지 않았다.
