## 현재 Unity 연결

`NativeMercenaryCatalog`가 현재 보유 기술/착용에서 목록·순서·한도를 계산하고, UI와 명시 승인 계약이 같은 목록을 쓴다. 런타임은 `Resources/OriginalMercenarySkills.json`을 읽는다. 기술이 수신/저장되지 않은 계정에 초기 직업 고용 기술을 소급 지급하지 않는다. 기존 `WorldDefinition.hires`만 쓰는 경로는 별도 호환 fixture용이며 현재 런타임의고정 재고가 아니다.

`Request_MercenaryItem`은4D/4E를 `Notify_MercenaryPacket`과 메타데이터 이벤트로 전달한다. 명시 원본 기록번호가 없으면 송신하지 않는다. 창의예상 수량은 저장하지 않으며 실제 소유·돈은 명시 `MercenaryAuthority` 승인과 저장 성공 뒤에만 변경한다. 해고 환급·자금·운영 한도 기본값을 만들지 않는다. 오래된 창/계정·중복 요청·저장 실패·동기 콜백의닫기/로그아웃은 후속 승인을 막거나 현재 표시를 복원한다. NPC/출입구 사용자 배치는 이번에 변경하지 않았다.

실행 가능한 검사와 실제 Unity 검증은 분리한다. 원본 DLL 전체 목록 계산,후기 요청·작업 사본·글꼴 인수를 x86으로 대조했지만 원작 전체 실행·GDI/Unity 픽셀·물리 마우스·청음 통과를 뜻하지 않는다. 최신 수치는 개별 보고서와 `설계/테스트_검증_계획.md`를 따른다.

## 구형1.2 확인 기록 — 현재 주소/실행 결과와 구분


Saver1.2 Saver.exe(기존 SHA256 9b74f465…)와 같은 설치본 setunit.dll을 정적으로 대조했다. 후기 실행 파일의 동일성이나 실제 원작 재생 확인은 아니다.

- 창 팩터리425DF0 부근의 문자열450C10은 `scene9.lsc`, 생성자는422C50이다. 원본 크기223×277, 제목은 ‘용병 리스트’다. 컨트롤5개는 순서대로 고용·해고·확인·위·아래다.
- 목록은422CC2에서(22,42)32×32 그림칸을35px 간격으로3열×3행 생성한다. 스크롤은3칸 단위이며 보유 그림은(155,39), 수량은별도 영역이다.
- 423810 고용: opcode4D + 캐릭터 word + 병종 word + 해당 병종의 고용가능수 word. 한 번에1명이다. 이미 병종이 있으면 그 병종을 사용하고 현재 수가 한도 이상이면 송신하지 않는다. 빈 상태에서만 목록 선택 병종을 쓴다.
- 423940 해고: opcode4E + 캐릭터 word + 현재 병종 word. 수량을1 줄이고0이 되면 병종을FFFF로 바꾼다. 버튼은 ‘판매’가 아니라 ‘해고’다.
- 두 함수는 선택 정보 payload+96 병종/+98 수량을 함께 사용한다. 앞선 표시 분석에서 이 두 필드의 의미를 미확정으로 남겼던 부분은 이 고용/해고 경로를 근거로 갱신한다. 전체 소유 유닛의 합계를 무조건 넣는 것이 아니라 선택 지휘관의 병종·수량이다.
- 목록은423640→setunit.GetSoldierList(10002840)에서 가져온다. 확인된 최종 중복 병종 병합10002B33은 최대 인원 중 큰 값을 유지한다. 기술 전체의 인원을 합산하지 않는다. DLL의 상위 기술 보정도 존재하므로 임의의 단순 전체 기술 합산으로 동일성을 주장하지 않는다.
- 원본 병종 가격/기본 능력치는 기존 MercenaryJobCatalog와 MercenaryHireCatalog의 변환 데이터를 사용한다. 클라이언트가 보내는 한도는 서버에서 재검사한다.
