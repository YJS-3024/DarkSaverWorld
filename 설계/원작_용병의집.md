# 용병의 집 — 원작 확인 및 구현 경계 (2026-10-29)

## 원본 근거

Saver1.2 Saver.exe(기존 SHA256 9b74f465…)와 같은 설치본 setunit.dll을 정적으로 대조했다. 후기 실행 파일의 동일성이나 실제 원작 재생 확인은 아니다.

- 창 팩터리425DF0 부근의 문자열450C10은 `scene9.lsc`, 생성자는422C50이다. 원본 크기223×277, 제목은 ‘용병 리스트’다. 컨트롤5개는 순서대로 고용·해고·확인·위·아래다.
- 목록은422CC2에서(22,42)32×32 그림칸을35px 간격으로3열×3행 생성한다. 스크롤은3칸 단위이며 보유 그림은(155,39), 수량은별도 영역이다.
- 423810 고용: opcode4D + 캐릭터 word + 병종 word + 해당 병종의 고용가능수 word. 한 번에1명이다. 이미 병종이 있으면 그 병종을 사용하고 현재 수가 한도 이상이면 송신하지 않는다. 빈 상태에서만 목록 선택 병종을 쓴다.
- 423940 해고: opcode4E + 캐릭터 word + 현재 병종 word. 수량을1 줄이고0이 되면 병종을FFFF로 바꾼다. 버튼은 ‘판매’가 아니라 ‘해고’다.
- 두 함수는 선택 정보 payload+96 병종/+98 수량을 함께 사용한다. 앞선 표시 분석에서 이 두 필드의 의미를 미확정으로 남겼던 부분은 이 고용/해고 경로를 근거로 갱신한다. 전체 소유 유닛의 합계를 무조건 넣는 것이 아니라 선택 지휘관의 병종·수량이다.
- 목록은423640→setunit.GetSoldierList(10002840)에서 가져온다. 확인된 최종 중복 병종 병합10002B33은 최대 인원 중 큰 값을 유지한다. 기술 전체의 인원을 합산하지 않는다. DLL의 상위 기술 보정도 존재하므로 임의의 단순 전체 기술 합산으로 동일성을 주장하지 않는다.
- 원본 병종 가격/기본 능력치는 기존 MercenaryJobCatalog와 MercenaryHireCatalog의 변환 데이터를 사용한다. 클라이언트가 보내는 한도는 서버에서 재검사한다.

발췌는 Tools/OriginalInputChecks/saver12-mercenary-*.asm.txt 및 saver12-soldier-list.asm.txt, 원본 그림 변환은 build_mercenary_ui.py / mercenary_ui_conversion.json에 보관했다.

## 이번 연결

- 기존 카오시아 용병의 집→Interior2900의 타일·출입구를 유지한다. 2900 실내의 좌측 카운터에 기존807 외형 NPC1명을 연결했다. NPC의 수·정확한 위치는 원작 확인값이 아니므로 `local-mercenary-counter`로 명시했다. 이전 사용자 요청의 상점 NPC 재사용 배치 범위이며 원본 MRC에서 NPC 배치를 발견했다는 뜻이 아니다.
- 대화 가능 위치는 NPC 인접 칸 또는 명시 카운터 앞(3,8)/(4,8)/(5,8)이다. 이동 중 클릭은 그리드 중앙에서 재시도한다. 서버가 장면·거리·그리드·입력 상태를 재검사한다.
- 원본 scene9 배경/버튼/목록을 Unity UI로 변환했다. 이전 임시 고용 패널과 시설/편성 바로가기는 이 서비스에서 표시하지 않는다.
- Request_OpenMercenary는 NPC 식별자를 사용하는 로컬 계약이다. 원작 NPC 오픈 opcode를 복원했다고 주장하지 않는다. 고용4D/해고4E만 확인된 원본 payload를 프레이밍해 로컬 서버에서 처리한다.
- 고용은 골드 차감·소유 목록 후보를 만들고 기존 계정 저장 성공 후 메모리에 반영한다. 실패하면 골드/소유 목록이 유지된다. 병사 ID20000부터의 할당은 로컬 서버 ID이며 원작 서버 할당법이 아니다.
- 중복 병종은 최대 한도를 쓰고, 보유 중에는 병종을 바꿀 수 없으며 마지막1명 해고 뒤 새 병종을 선택한다. 주 캐릭터100의 고용을 우선 연결했다. 추가 지휘관의 초기 프로필/고용 규칙은 임의로 채우지 않는다.
- 현재 해고는 골드 변동 없이 처리한다. **원작 서버의 환급 여부는 클라이언트 송신만으로 확정되지 않았다.** 이 동작을 원작 환급 정책 확인으로 보고하지 않는다.
- 초기 마법 목록이 미확정인 MP 사용 병종은 고용을 거부한다. MP=-1 병종은 미사용으로 처리한다. 고용은 소유 저장을 만들지만 실제 전투 입장의 서버 편성/출전 배치까지 완료한 것은 아니다.
- 오래된 저장의 미분류 용병을 자동으로 새 고용 타입으로 변환하지 않는다. 기존 실패 저장은 변경하지 않았다.
