## 확인된 원본 상태그림 우선 적용 (2026-10-25, 최신)

- 사용자 지시: 알 수 없는 부분은 제외하고, 원작과 다르며 원본 근거가 확인된 부분을 원작 위주로 수정한다. 기존에 사용자가 확정한 초기자금/회복/매입/AP/진행 정책은 변경하지 않는다.
- 상세상태창0x10005410에 더해 부대/축소창의0x1000641D~0x100064E4,0x10006822~0x100068EE도GetCharSurface의고정RECT(32,32,64,64),표시코드/100==7의64px축소분기를사용함을확인했다. 원본배열프레임으로는Down[1]이다. 현재방향/이동/공격프레임을이그림으로사용하는것은원본과달랐다.

## 전투 상태창의 그림 종류 재확인 (2026-10-25)

- 원작 상세상태창의 그림은 대사/캐릭터선택용 얼굴 초상화가 아니라 캐릭터 스프라이트 표면에서 가져온 그림이다. GameCtl0x100054AB에서getsnum(IAT0x1001627C) 후GetCharSurface(IAT0x100162B4)를 호출한다. 별도의GetFace는IAT0x1001626C이며 이 그림 분기에서 사용하지 않는다.
- 일반 분기0x10005563~0x1000559F는 원본표면RECT(32,32,64,64)를32×32로 창원점+(44,79)에 그린다. 표시코드/100==7인 별도 분기는RECT(64,64,128,128)를같은32×32영역으로축소한다. 종전 ‘초상’ 표기는 이 상태그림과 얼굴초상화를 혼동할 여지가 있으므로 구분한다. 실제원작실행/타이밍을 확인한 것은 아니다.
- 현구현 대조: 전투의BattleMapPresentation.GetUnitPortrait는현재Body.sprite를반환하므로 얼굴카탈로그를사용하지는않지만, 원본의고정소스RECT와현재방향/애니메이션프레임은동일하다고볼수없다. 월드WorldSessionHud는CharacterPortraitCatalog의64×64얼굴을같은자리32×32로표시하며 이는앞선싱글판재사용으로 원작전투상태창근거와다르다. 두경로를구분하고원본상태그림정합작업대상으로남긴다.
- 코드발췌/임포트근거: `닥세_리소스/분석결과/UI_전투상태창_캐릭터그림_근거.asm.txt`. 이번요청에서는그림종류를확인했으며런타임표시는변경하지않았다.

EA는 원본9열이며 수치 정책용 절댓값을1~10000으로 제한한다. 지속 효과의 시간은 원본10열을5~90초로 제한해 사용한 로컬 설정이다. 이는 해당 원본 열이 서버에서 실제로 초를 뜻한다는 결론이 아니다. AP는ceil(원본 TICK/5)를1~10으로 제한한다. MP는 원표 값 그대로다. 음수 범위는 거리 대신 원본 방향 기하 모드로 사용하고, 로컬 승인 거리 한계는255로 두어 원본 격자 선택을 불필요하게 막지 않는다. 범위0의 자기 중심 효과와 양수 범위는 별도 로컬 거리 한계를 사용한다. Unit8은 원본0~8의9슬롯을 확인하고 현재 상태·진영·사거리 조건을 만족하는 멤버만 묶는다.

범위 효과는 대상 중복을 제거하고 전체 대상 검증 후 AP/MP를 한 번만 지출한다. HP·MP 흡수는 전체 실제 변화량을 합산해 시전자에게 한 번 반영한다. 모든 대상 상태를 반영한 뒤 표시 이벤트를 보낸다. 아이템 연결 마법은 기존 아이템 AP/소비 경로를 쓰며 마법의 MP를 중복 부과하지 않는다. 상태는 전투 내 일시 효과이며 저장 형식을 새로 만들지 않았다.

검증: `Tools/AbilityChecks/run_checks.py`는 새로 컴파일한 실제 프로덕션 런타임 DLL의 CombatFlow/LocalCombatAuthority를 .NET에서 실행한다. Unity 씬/네이티브 엔진 호출 없이439개 분류와374개 효과·비용·실패 원자성·흡수 합산·부활/점유·면역·아이템 MP 예외·상태 만료를 검사한다. `all_abilities_check.json`은 각ID의 정책/원본 범위·비용과 원표/런타임 해시를 보존한다. `check_all_abilities.py`는 전체 클래스178개 참조ID, 고용 병종67종,439개 연출 메타데이터 및 감정표현59프레임을 대조한다. Unity의 실제 메뉴 클릭·모든 직업 플레이·청음·밸런스·원작 재생 타이밍은 별도 미검증이다.


## 2026-10-18 클래스 변경 기술 병합·저장·전투 메뉴 묶음

- 사용자 확정: 기존 마법은 유지하고 새 마법을 추가한다. 동일 마법의 레벨만 다르면 높은 레벨 하나로 교체한다. MagicCatalog의 명시적인 `이름(LvN)`으로 계열·레벨을 식별해 병합한다. ID 크기를 레벨로 추정하지 않으며 미확인 ID·동일 계열/레벨의 서로 다른 ID는 실패 처리한다. 레벨 표기가 없는 기술은 동일ID만 중복 제거한다.
- `NativeCharacterProfile.TryBuildClassChange`는 원본 다음 클래스 연결과 첫 행 목록으로 새 프로필을 만든다. 원본 프로필은 변경하지 않고 기존 마법을 병합하며 사용기술은 다음 클래스의 정확한 목록으로 바꾼다. 기존 무기술 프로필은 현재 클래스 첫 행의 마법을 기반으로 최초 변경 목록을 만든다. `confirmedLevel`은 외부 확인 입력이며 자체 XP 자격 판정이 아니다. HP/MP·성장·전직 비용을 추정하지 않는다.
- 프로필에 선택형 `hasClassAbilities`/마법ID/사용기술ID 저장 필드와 깊은 복사를 추가했다. 기존100 직업 저장은 호환되며 자동 기술 지급하지 않는다. 확인된 기술 상태가 있는100~169 프로필을 저장/복원할 수 있으나 시작 생성은 여전히100만 허용한다. JSON 직렬화→NativeSaveStore 유효성 검사→세션 복원/재캡처를 검증했다. 디스크 저장 API 자체의 기존19건 회귀도 통과했다.
- 전투 진입 시 확인된 프로필 기술 상태를 단일 주인공의 마법·특수기 메뉴와 요청 허용 목록에 연결한다. 고용/패시브 분류 ID는 프로필에 보존하되 전투 마법 메뉴에 넣지 않는다. 미확정 특수기 효과나 원본 요청 비용을 창작하지 않는다. 추가 아군의 기존 편성 기술 목록은 유지한다. 잘못된 카탈로그 연결이면 출전을 보류한다. 클래스 체인지 인게임 UI·XP/레벨 자격 판정·현재 세션에 변경 프로필을 적용하는 전직 명령 및 외형/바이탈 전환은 아직 연결하지 않았다. 테스트는 데이터/저장/메뉴 API 경로이며 실제 Play 전체 흐름 검증은 아니다.

## 최신 임시 규칙 승인 및 적용 범위

사용자가 미확정 공식은 임시로 적용하고 테스트하면서 변경하는 방식을 승인했다. 아래 값은 **원본 복원 확정값이 아닌 싱글게임용 임시 규칙**이다. `GameConstants`의 `BattleTemporary*` 값을 수정하여 조정한다. `BattleUseTemporaryLocalRules`를 끄면 실제 플레이도 기존 근거 확인용 요청/독립 통지 방식으로 돌아간다. 기존 확정 AP·이동·사망·복귀 MP 규칙은 유지한다.

- 실제 전투의 Start에서 임시 모드를 활성화한다. 공격 AP는 파이터100=7·히어로115=6·카이저135=5, 나머지 아군4/적군6을 임시 기본값으로 사용한다. 명시 설정된 양수 비용이 있으면 우선한다. 시연 파이어볼101은 AP6·MP10·사거리6이다. 원표의 TICK를 확정 비용으로 자동 환산한 것이 아니다.
- 기본 명중90%·회피5%와 승인한 명중×(1−회피) 공식을 적용한다. 명시 확률이 있으면 우선한다. 물리 피해=max(1,공격−max(0,방어)), 파이어볼 피해=max(1,공격+20−max(0,방어/2 정수)). 최소 피해·마법 보너스·방어 제수·MP 비용은 상수로 분리했다. 임시 판정으로 HP0이 되면 제거 상태로 전환하며 사망 애니메이션을 추가하지 않는다.

## 기준

### 이동·기본 공격·휴식 UI 우선 연결

표시 계층을 `OnGUI` 임시 패널에서 런타임 UI Toolkit(`UIDocument`·`PanelSettings`)으로 전환했다. 시작/캐릭터 생성·마을 HUD·부대 편성·전투 HUD/명령/마법 선택·결과/전환 안내가 같은 어두운 금색 테두리 테마를 사용한다. 생성·이어하기·저장·시나리오 이동과 전투 요청 API는 유지한다. 개발용 아이템/마법 카탈로그 버튼과 단축키는 기본적으로 숨기며 실제 인벤토리/습득 마법으로 위장하지 않는다. UI는 플레이 중 컴포넌트 아래에 생성하므로 미저장 씬을 강제 저장하지 않는다. 65개 관련 검사 직접 호출 통과 및 콘솔 오류0을 확인했고, 실제 Game View 외형 검증은 별도 필요하다.

전투 HUD 입력 영역에 세 명령 버튼을 상시 표시한다. 선택 아군의 HP·MP·AP는 막대와 수치로 표시하고 이동 중/행동 준비/AP 회복 상태를 보여준다. 이동과 공격은 버튼 선택 후 각각 빈 칸·적을 클릭해야 실제 행동이 시작되며 버튼 선택만으로 AP를 차감하지 않는다. 휴식은 버튼 클릭으로 즉시 실행한다. AP 부족·이동 중·HP 최대·비활성/종료 상태에서 유효하지 않은 버튼은 비활성화한다. 기존 겹치던 별도 휴식 버튼은 제거했다.

기본 공격은 기존 로컬 요청 경로로 피해/미스를 적용하고 안내 영역에 결과를 표시한다. 휴식은 위 승인된 임시 회복/AP 규칙을 사용한다. 명령 패널 클릭이 바닥 이동·공격으로 새지 않도록 기존 포인터 차단 영역 안에 배치한다. 우클릭/Esc 취소와 마법 대상 선택 취소는 유지한다. 원본의 최종 이미지·스킨을 모두 재현한 것이 아닌 기능 우선 UI이며 버프/원본 공격 프레임은 이 범위에서 구현하지 않는다.

검증: UI·맵 입력・요청 전달 검사51개를 Unity에서 직접 호출해 51/51 통과했다. 새 통합 검사에서 버튼 선택 무차감→바닥 클릭 이동(AP4)→이동 중 잠금→휴식 HP 회복/AP4→HP 최대 휴식 차단→적 클릭 기본 공격/피해/AP 차감을 확인했다. 세 버튼이 안내 영역 안에 있고 겹치지 않으며 클릭이 맵에 전달되지 않는 것도 검사했다. 보조 컴파일 오류0(기존 경고30), Unity 콘솔 오류0, Start 미저장 상태 보존. 실제 Game View의 외형・가독성 육안 확인은 아직 하지 않았다.

원본 분석을 중심으로 분석 확정 사실·기존 사용자 지정·미확정 사항을 구분한다. 데이터로 확인 가능한 내용은 먼저 대조하며 중복 질문하지 않는다. 이 문서는 구현 완료 선언이 아니다.

상세 근거는 `08_클라이언트_정적_분석.md`, 그림·통행 검증은 `08_원작_수직슬라이스.md`, 적용 상태는 `10_분석_적용_진행표.md`를 참조한다. 현재 확인된 `BattleSceneRoot`는 1대1 공격·반격 시연이다. 과거 아군 3명·적 3명·실시간 AP 설명은 현재 구현 사실로 취급하지 않는다.

### AI·직업·지형

- AI는 최대 100개 ID 원형 큐를 호출마다 하나씩 처리한다. 큐 크기는 한 전투의 인원 상한을 뜻하지 않는다.

### 시간·행동·이동

- 완전 실시간, 명령 선택 중에도 진행. 아군 자유 선택, 행동 후 자동 다음 유닛 선택 없음. 최신 사용자 확정: AP가 최대치 10에 도달해야 행동을 시작한다.
- 시작 AP 6, 최대 AP는 아군10·적군20; 양쪽 모두1초마다 AP1 자동 회복. 각자의 최대치에 도달해야 행동을 시작하고 행동별 비용만큼 차감한다. 이는 최신 사용자 지정이며 원본 최대값 확인이 아니다. 직전 양쪽 최대20 설정을 대체한다. 이동 행동당 차감은 아군4·적군6을 유지한다.
- 이동 비용 아군 2·적군 4. 한 칸씩 통행·점유 재검사, 목적지가 겹치면 이동하지 않는다. 아군 통과 허용, 적군 통과 불가.
- 먼저 시작된 행동 우선: 공격 후 이동 허용, 이동 후 공격 불가. 세부 적중·취소 시점은 미확정이다.
- 휴식도 하나의 행동이며 연속 행동 불가. 별도 방어·대기 명령 없음.
- 일반 공격 사거리는 클래스별, 마법 사거리·범위는 레벨과 무관하게 고정, 고유 기술은 레벨별 변화. 원거리 공격은 사거리 내라면 지형 무관이라는 기준을 자료와 대조한다.

과거 시연 비용(이동 4·공격 2·기술 5·마법 6·아이템 3·휴식 4)은 원본 확정값이 아니다. 사용자는 공격은 클래스별, 마법은 마법별로 다르다고 설명했다. 공통 공격 2·마법 6을 적용하지 않는다. 확인한 원표 근거와 환산 경계는 아래와 같다. 마법 요청의 계산 비용/최종 MP 분석은 AP 비용과 구분한다.

- 직업 원표 `catalogs/jobs.csv`의 70개 항목에 이틱감(24열, 0기준)·공틱감(25)·휴틱감(26)·마틱감(27)이 있다. 공틱감은 4~9로 직업별 차이가 있으며 파이터 100은 7, 히어로 115는 6, 카이저 135는 5다. 기존 Unity JobCatalog에도 해당 열은 이미 원문 값으로 보존된다.
- `converted/Magictbl.csv`의 439개 항목은 MP(5열)·시간(6열)·TICK(12열)을 별도 보관한다. 파이어볼 101~103의 TICK은 10, 104~106은 9, 파이어 201~203은 15다. 전체 TICK에는 0 및 최대 25가 있다. 직업 마틱감은 40~100이므로 TICK을 곧바로 최대 AP 10의 차감값으로 취급하거나 마틱감을 100분율로 가정하지 않는다.
- '비용 데이터가 없다'는 이전 설명은 부정확했다. 관련 원표 값은 있으며 최종 AP 비용으로 쓰는 조합·단위·반올림 규칙을 추가 확인해야 한다. 공통 GameConstants 비용 0은 이 미확정 상태의 표시이며, 최종 비용이 설정되지 않은 요청은 실행하지 않는다. 행동자별 공격 비용과 마법 ID별 비용 설정 경계는 구현됐으나 자동 원표 바인딩은 아직 아니다. 이동은 위 사용자 지정이 우선이다.

최신 설정 변경: GameConstants.BattleAllyMaximumAp=10·BattleEnemyMaximumAp=20. BattleMaximumAp은 단독 아군 AP용 호환 상수이며 실제 전투는 유닛 진영별 최대치를 사용한다. 스냅샷 MaxAp·UI 막대/수치·AI 준비·절대 틱 수신·공격 비용/편성 검사를 연결했다. 공통 마법 비용 등록은 양 진영 중 큰 상한까지 허용하되 실제 시전 시 시전자 상한을 재검사한다. 마법별 RawTick은 보존하며 미확정 환산이나 상한으로 자동 축소하지 않는다. 아래 공통 최대20 검증 기록은 이전 설정의 이력이다.

최신 진영별 검증: 무인자 전투 검사256개와 AP 경계 매개변수6개, 합계262개를 Unity에서 직접 호출해 통과했다(Test Runner 전체 실행 아님). 아군은4초 후10, 적군은14초 후20 준비·이동 후6/14·진영별 비용 경계와 절대값 상한·소유 스냅샷을 확인했다. 런타임 보조 컴파일 오류0/기존 경고30, Unity 콘솔 오류0, Start 미저장 상태 보존.

#### 틱 처리 코드 추가 확인

`userunit.dll`·`setunit.dll`을 실행하지 않고 PE 명령을 정적으로 읽었다. 아래 주소는 ImageBase `0x10000000` 기준 VA다. `Tools/CombatApChecks/`의 분석 도구로 재확인할 수 있으며 원본 입력의 SHA-256 변경 여부도 검사한다.

- `IncTick` (`0x1000C6B0`): 유닛 배열의 레코드 간격은 `0x2E0`. 유효 레코드의 현재 틱 `+0x60`을 1 증가시키고 최대 틱 `+0x5C`로 제한한다. 이 함수 자체는 호출 주기나 직업별 행동 비용을 계산하지 않는다.
- `SetTickMenu` (`0x1000C720`, 대입 `0x1000C8BD`): 전달받은 현재 틱을 0~최대 틱으로 제한해 절대값으로 대입한다. 비용을 빼는 함수로 해석하지 않는다.
- `resetcharacter(unitinfo*)` (`0x1000B0A0`): 입력 구조의 `+0x58`을 유닛 최대 틱 `+0x5C`에 복사 (`0x1000B293`), 입력 `+0x5C`를 현재 틱 `+0x60`에 복사 (`0x1000B3FD`). 이 경로만으로 원본 최대 10·시작 6을 증명할 수 없다. Unity에서는 사용자 확정값을 유지한다.
- `CommanderAIAction` (`0x10004300`) 내부 `0x1000466F/0x1000468B`는 명령 처리 후 현재 틱을 0으로 만든다. 이는 클라이언트 AI의 임시 상태 갱신 근거이며 직업별 최종 비용 차감 공식이나 사용자 플레이어의 모든 행동 규칙으로 일반화하지 않는다.
- `GetMagicTbl2` (`0x100025C0`)는 간격 `0x140`의 신형 레코드를 직접 찾는다. `GetMagicTbl` (`0x10002600`)도 같은 자료를 조회한 뒤 구형 반환 버퍼로 필드를 변환한다. 따라서 구·신 테이블이 서로 무관하다는 해석도 부정확하다. GameCtl의 요청 비용 계산에서 읽는 구형 필드를 신형 TICK과 임의로 동일시하지 않는다.

#### 신형 마법 필드와 요청 계산값의 구분

`setunit.dll` 로더의 `sscanf` 출력 인자 순서 (`0x10001FD6~0x10002023`)로 신형 레코드의 17개 필드 배치를 확인했다. ID `+0`, 이름 `+4` 뒤에 숫자 필드가 `+0x104`부터 배치된다. `check_magic_layout.py`는 인자 순서·17개 변환 지정자·구형 필드 복사 및 GameCtl 두 요청 경로를 검증한다.

| 원표 필드 | 신형 오프셋 | 구형 반환 버퍼 |
| --- | --- | --- |
| MP | `+0x110` | `+4`로 복사 |
| 시간 | `+0x114` | 확인한 직접 필드 복사에는 없음 |
| TICK | `+0x12C` | 확인한 직접 필드 복사에는 없음 |
| 번호(ID) | `+0` | `+0`으로 복사 |

GameCtl의 `0x1000E421~0x1000E43D`, `0x1000E572~0x1000E58E`에서 요청 계산값은 구형 `+0x170/+0x14/+0x10/+0x0C/+8`의 합에 `+0`을 곱한다. 필드 변환과 대조하면 `ID × (속성 + 유닛 + 팀 + 범위 + 거리)`다. 곱셈의 피연산자는 MP가 있는 `+4`가 아니다. 이는 확인한 바이너리의 실제 연산이며, 이 특이한 계산의 서버 측 의미나 정상 비용 공식 여부까지 확정한 것은 아니다. 이전의 '마법 요청 계산 비용' 명칭도 AP/MP 소모량의 확정 근거로 사용하지 않는다.

Saver.exe의 `GetMagicTbl2` 직접 호출은 5곳이며, 확인한 정보 표시 구간 `0x0041A595`는 MP `+0x110`, 이어 거리·범위를 읽는다. 다른 호출 직후에는 아이콘 좌표를 사용한다. 이 호출 목록만으로 TICK의 모든 소비 지점이 없다고 단정하지 않는다. 캐시된 포인터와 별도 접근은 추가 추적 대상이다.

현재 확인 범위에서는 직업 공틱감·마틱감과 마법 TICK을 조합한 최종 AP 환산 공식까지 연결하지 못했다. 남은 추적 대상은 신형 TICK의 소비 지점과 직업 능력 필드의 소비 지점이다. 원표 자동 바인딩은 아직 미적용이다.

### 실제 플레이 연결 확인 (2026-10-12)

- 생성한 플레이어도 직업 카탈로그의 기본 열 2/4/6/8(체력수·마력수·공력수·방력수)을 사용한다. 기존 시연 능력치와 몬스터 원본 기본 수치가 혼용되던 경로를 수정했다. 저장된 남은 HP/MP는 기본 능력치 적용 후 복원하며 서버 레벨·성장·장비 공식은 적용하지 않았다.
- `Brugos01_Play`에서 별도 검증 캐릭터와 저장 경로를 사용해 진입→이동→공격→휴식→패배 결과창→전투 씬 해제→월드 조작 복구를 Play 모드에서 확인했다. HP/AP 강제 변경은 하지 않았다. 키스라 솔로 처치·승리 경로를 검증한 결과는 아니다. 기록·화면은 `Tools/CombatRulesChecks/Play-20261012-080956/`에 있다.
- 실제 공격 결과의 피해 숫자와 MISS를 표시한다. 단순 HP 동기화는 공격 표시로 해석하지 않는다. 최신 사용자 확인과 원본 `userunit.dll` 정적 분석에 따라 글자 표시는 `board.bmp`의 숫자·MISS 이미지로 교체했다. `0x1000B4E0`은 X=`227+셀번호*8`, Y=`418+색행*18`, 8×14 숫자 셀을 사용하며 0은 셀10, +는11, -는12다. `0x1000F950`의 일반 HP 감소 표시 분기는 빨간색 행0을 사용한다. MISS 분기는 `0x1000FC2A`~`0x1000FC6D`의 (1,447,36,11) 이미지를 사용한다. 숫자 네 색행과 MISS를 Unity 시트로 변환했으며 노랑을 치명타로 임의 지정하지 않았다. 표시 크기는 `BattleFeedbackPixelScale`로 조절한다. 상승 속도/시간은 기존 임시 표시 값이며 원본 궤적까지 복원한 것은 아니다.
- 기본 공격 표시의 Fx2 참조를 추가 복원했다. `userunit.dll`의 `0x1000E6E7`~`0x1000E742`는 Fx2 표면을 `0x1010A3B8`에 저장한다. `0x1000FFD7`~`0x10010044`는 X=32, Y=`((counter/2)%4)*32`의 32×32 영역을 그린다. 공격 상태 카운터는 `0x100105D8`~`0x10010670`에서 진행되고 48 초과 시 해제된다. 가까운 대상의 반 타일 오프셋은 `AttackChar(0x1000CEE0)`의 거리 조건을 따른다. 변환한 네 프레임만 Unity 자산으로 사용하며 원본 BMP를 플레이 중 읽지 않는다. 카운터의 실제 시간 환산은 미확정이므로 `BattleAttackCounterSeconds`는 조절 가능한 임시 값이다.
- 피해·MISS 이동 궤적 추가 복원: `userunit.dll`의 `0x10015260`에는 Y 오프셋 `0,-4,-5,-4,0,1,4,10,4,1,0,1,4,10`이 있다. `0x1000FB8E`와 `0x1000FC48`은 이 표와 카운터의 X 이동을 각각 숫자와 MISS에 공통 적용한다. 단계0은 표시하지 않고 1~13을 표시하며 단계14에서 숨긴다. 기존 직선 상승을 이 원본 궤적으로 교체했다. 실제 시간 환산과 화면 기준점은 원본과 동일하다고 확정하지 않았으며 표시 시간은 `BattleFeedbackSeconds`로 조절한다. 앞 항목의 ‘기존 임시 상승 움직임’ 기록은 이 궤적 복원으로 대체한다.
