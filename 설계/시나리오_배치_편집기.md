# 시나리오 편집툴과 원본 배치

Unity 메뉴 **DarkSaver → 시나리오 편집툴**에서 연다. **원본 배치 보기** 또는 **[원본 SET/POS]** 항목을 선택하면 설치본에 있는 배치를 읽는다. **[시나리오 대본]**은 해당 맵의 원본 대사·연출·이벤트 확인용이다. 초기 편성이 없는 맵에 보완 몬스터를 자동 생성하지 않는다.

## 현재 적용한 배치

| 구분 | 대상 | 현재 상태 |
| --- | --- | --- |
| 원문 SET/POS | 26,51~55,314~323 | 16맵·610몬스터, 원문 직업/좌표/수량 유지 |
| 아군 위치 슬롯 | 위16맵 | POS195칸, 직업 미정·읽기 전용 |
| 초기 편성 미확보 | 01~17,33,330~333,404~406 | 보완1105마리 삭제, units빈 배열·서버 통지 대기 |
| 수련장·대련장 | 101~107·201~207 | 기존 편집 항목 유지, 원본 미확정 편성을 생성하지 않음 |

3인 편성·2칸 간격·12마리씩 출현하는 싱글판 보완 규칙은 배치 근거에서 제거했다. 생성기·보완 배치 JSON/CSV·정돈 도구도 삭제하거나 사용 중지했다. 원문 편성이 없는 맵의 빈 배열은 원작에 몬스터가 없었다는 의미가 아니다.

원문 자료에 있는 SET/POS는 클라이언트에 포함된 데이터임을 확인한 것이다. 원작 서버가 실제로 그 편성을 자동 로드했다는 사실까지 증명한 것으로 표시하지 않는다. 연출 CHARPOS와 AI AREA를 전체 초기 전투 편성으로 바꾸지 않는다.

## 파일과 런타임 연결

- 공용 배치: `Assets/_Game/Resources/Scenarios/Original/{맵번호}/Deployment.json`.
- 편집툴 목록: `Assets/_Game/Editor/BattleLayouts/OriginalIndex.json`.
- 편집툴 그림: `Assets/_Game/Editor/BattleLayouts/Art/{job}.png`.
- 대본·연출·이벤트: `Assets/_Game/Resources/Scenarios/{번호}/Content.json`.
- 원문 추적 자료: `분석/Saver_Late/scenario_monster_placements.json`과 원본 SET/POS.

편집툴과 `OriginalScenarioDeployments.TryLoad`는 같은 Deployment 리소스를 사용한다. 로컬 서버 매니저의 `TryGetOriginalScenarioDeployment`로도 조회한다. 데이터 조회 성공이 실제 입장/등장 통지를 의미하지는 않는다. 입장·등장·전투 판정은 서버 통지 경로가 결정한다.

이전 Editor/BattleLayouts/Original{번호}.json 복사본은 공용 리소스로 이동했다. JSON 메타 GUID는 유지한다. 실제 맵 씬에 몬스터 GameObject를 굽거나 저장 계정을 수정하지 않는다.

## 번호와 좌표

- `id`: 원문 unit, 맵 안의 개체 식별번호. 배열 순번이 아니다.
- `job`: 몬스터 종류/능력치 표의 ID. 직그림 번호는 별도이며61직업이36직그림을 참조한다.
- `x`,`y`: 좌상단0,0 기준 원문 정수 타일 좌표. 화면 변환에서만 Unity Y축을 뒤집는다.
- `sourceRows[].setLine/posLine`: 빈 줄·주석을 포함한 원문1기반 행 번호. 배치/등장 순서가 아니다.
- `sourceRows[].extra`: 원문 추가값을 해석하지 않고 보존한다.

후기 코드의 지휘관은 `id/10*10`이다. 확보된122부대는400~404,410~414처럼 지휘관 슬롯0+부하1~4를 사용한다. 편집툴의 기본 부하 추가 범위도1~4다. 코드가 같은 지휘관을 참조할 수 있는 ID 범위와 원문에서 사용한 부하 수를 구분하며, 모든 원작 부대의 최대 인원을 증명한 것으로 일반화하지 않는다.

관측한5인 대형은 대각 네 귀퉁이65부대, 상하좌우44부대, 좌우+아래2칸12부대, 뒤쪽V형1부대다. 원문 좌표를 새로 정돈하거나 동일 간격으로 강제하지 않는다. 지휘관이 없으면 경고하고 첫 부하를 지휘관으로 대체하지 않는다.

## 조작

- 시나리오 선택: preview scene에 맵을 표시한다. 사용자가 열어둔 실제 씬을 교체하거나 저장하지 않는다.
- 전투/연출 토글: 전투 몬스터와 도입 CHARPOS를 분리한다. 연출은 읽기 전용이다.
- 몬스터 선택/편집: 맵 클릭 또는 부대 목록에서 선택한다. 드래그/좌표 입력·종류·이름·기본 수치를 편집한다. job변경에 따른 기존 수치 자동 재계산은 아직 없다.
- 지휘관/부하 추가·삭제: 원본 배치와 별도 편집 전장에서 사용한다. 원본 초기 편성이 없는 대본 항목에서는 보완 몬스터 추가/저장을 막는다. 초기자료가 비었다고 몬스터나 승리를 생성하지 않는다.
- 부대 필터: 지휘관 ID만 사용한다. 웨이브 UI/출현 단계 필터는 없다. 표시/전체/겹침 수와 전체 몬스터 보기 버튼으로 확인한다.
- 대형 참고: 원문4종의 미리보기·선택 지휘관 기준 윤곽선이다. 켜거나 선택해도 실제 수량·좌표가 바뀌지 않는다.
- AI 이동 기준: AREA를 청록 영역, SOILDER의 유닛 참조를 점선으로 표시한다. 소속이나 초기 출현 좌표로 사용하지 않는다. 원문 AREA/POS가 엇갈리는6건을 자동 보정하지 않는다.
- 아군 위치: 원문 POS의 파란 슬롯은 읽기 전용이며 계정/직업을 임의 배정하지 않는다. 대본 항목의 기존 진입 후보는 별도 표시다.
- 상자/이벤트: CHANGESPRITE·CHARPOS 조건의 위치를 읽기 전용으로 표시한다. 독립 퀘스트 배치표라고 추측하지 않는다.
- 탐색: 휠은 커서 기준 확대/축소, 가운데 드래그는 화면 이동이다. 지도/표식/라벨/참고선은 뷰어 안으로 잘라 표시한다.

## 저장과 상태

원본 배치 편집은 공용 Deployment 리소스에 저장하며 `placementEdited`를 표시한다. 원문 행 참조·추가값·아군 슬롯은 보존한다. 분석 폴더의 원문을 수정하지 않는다. 원문/미저장 편집/저장된 편집 상태를 구분한다.

외부 수정 충돌, 범위 밖 좌표, 잘못되거나 중복된 ID는 저장 거부한다. 원본 자료가 없는 Content에 임의 몬스터를 저장하는 것도 거부한다. 대본·연출·이벤트·화면 자료는 삭제하지 않았다. 자료 변경에 따른 콘텐츠/비주얼 해시는 동기화했다. 원문 미확보 상태로 초기화·자동 클리어·보상을 승인하지 않는다.

기존 싱글판 진행 저장의 파일은 건드리지 않는다. 해당 진행이 새 배치/해시와 맞는다고 승인하거나 새 편성으로 자동 변환하지 않는다. 원작 서버가 제공한 유닛/진행 상태는 별도 통지로 처리해야 한다.

## 재현·검증

```bash
python Tools/ScenarioPlacementChecks/build_original_editor_layouts.py
python Tools/ScenarioPlacementChecks/apply_original_deployments.py --apply
python Tools/ScenarioPlacementChecks/check_editor_troops.py
```

원본 편집본을 UI나 외부에서 수정한 경우 첫 명령은 중단한다. 명시적 `--reset`만 원문 복구에 사용한다. 삭제한 보완 생성기로 돌아가지 않는다.

검증 결과는 `Tools/ScenarioPlacementChecks/original-deployment-cleanup.json`, `original-editor-layouts.json`, `editor-troop-check.json`이다. 원본610개·아군195개·61그림·소스 행/추가값, 보완1105개 삭제·25개 대본/진입/지형 유지·비주얼 해시·재실행 불변·빈 편성 초기화 거부·데모 생성 차단을 검사한다. 실제 Unity에서의 그림 임포트/창 표시/드래그/저장 재열기·서버 등장 통지·플레이 검증은 별도로 확인해야 한다.
