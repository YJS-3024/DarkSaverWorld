# 테스트·검증 계획 및 인계

## 이번 커밋의 실제 Play 검증 인계 (2026-10-27)

대상 브랜치는 `work`다. 검증 시작 시 `git rev-parse HEAD`와 Unity 버전을 기록하고 아래 순서로 진행한다. **원작과 동일한 기능의 구현 완료 판정이 아니라, 현재 연결한 로그인→원본 전투 튜토리얼 경로의 실제 동작 검증이다.** 아래 「가입→캐릭터→안내 튜토리얼」의4페이지 안내 검사는 폐기된 이전 기록이다.

| --- | --- | --- |
| 0 | 임포트·컴파일, 관련 EditMode 실행 | Console 오류·예외·Assert와 TestRunner의 통과/실패/무시 수를 각각 기록. 소스 컴파일과 TestRunner 실행을 구분 |

검증 원칙:

- 기존 실패 저장은 원본과 SHA256 목록을 보존하고 사본/별도 신규 저장으로만 검증한다. 진행을 위해 HP·돈·마법·아이템을 주입하거나 이전 저장으로 덮어쓰지 않는다.
- 신규 영구 능력치·초기 자금·보상은 현재 미확정 서버 경계다. 과거 싱글판의 HP200/MP45·30,000골드·무료 회복 등을 현행 필수 기대값으로 사용하지 않는다. 실습에 등장하는 능력표/HPSET 수치와 영구 캐릭터 상태를 구분한다.
- AP 그래프·시체 애니메이션·일부 창 내용·정확한 경로/연출 타이밍·F7 상위 처리·선행 대기실 수업은 미완성/미확인으로 기록한다. 원작 동일 통과로 세지 않는다. 카오시아 복귀 확인과 미구현 일반 월드 이동/전투는 구분한다.
- 차단 시 최초 실패 단계, 기대/실제, 직전·직후 저장 사본/해시, 화면, Console 로그, 재현 순서를 남긴다. 이후 미실행 항목은 미실행으로 표시한다. 재생 상태 관찰은 청음 통과가 아니다.
- 현재 클라우드의 실제 Unity Play/TestRunner는 라이선스 제약으로 미실행이다. 아래 컴파일·오프라인 검사 기록을 실제 Play 통과로 옮기지 않는다.


## 최신 변경: 원본301 전투 튜토리얼 실행 연결 (2026-10-27)

기존 계정 안내4페이지를 삭제하고 `TUTORIAL.DEO`의420개 명령/100개 대사를 읽는 전용 실행기로 교체했다. 아래 과거4페이지 안내 기록보다 이 절이 우선한다. **대본·입력·저장 연결 완료와 원작 화면/타이밍의 완전한 재현은 구분한다.**

- 신규 계정→로그인→로컬 서버 선택→10슬롯/최초 직업 선택·생성 경로를 유지한다. 플레이 진입 후 원본 `Map_301_;`을 추가 로드하고 기존 카오시아 화면을 보존한 채 가린다. 맵301을 빌드 목록에 추가했다. 대본 END를 저장한 뒤 카오시아 화면과 카메라를 복원한다. 저장된 월드 위치21,21과 경제/장비/영구 능력치는 변경하지 않는다.
- 플레이어000, 교관100/직업125, 연습 상대400·410/직업301, 용병001·002/직업201, 전령800/직업805를 원문대로 구분했다. 원본 그림108프레임, 교관의 동맹/적 팔레트, `nco01` 음악을 연결했다.
- 이동 메뉴/지정 타일 도착, 공격 메뉴/지정 대상, 휴식, 마법3단계, 용병 명령, F2/F3, 캐릭터 가리키기, 동맹 체크의 서로 다른 입력을 검사한다. 일반 ‘다음’ 클릭으로 실습을 건너뛰지 않는다. DO는 원문 밀리초 대기, 이동 완료 대기는 실제 표시 이동 완료 후 요청한다. 정상 동작만 해당 캐릭터의 로컬 ServerManager 처리→저장→응답으로 반영한다.
- 상태는 `NativeTutorialProgress` v2의 대본 커서/실습 캐릭터/창/하위 메뉴/목표 위치로 저장한다. 마법 선택 중·자동 이동 중 재접속도 복원 대상으로 포함한다. 이전 v1의4페이지 안내 완료는 원작 실습 완료로 인정하지 않고 원본 첫 입력 대기로 이행한다. tutorial=null인 예전 저장에는 강제 재생을 추가하지 않는다.
- 신규 대화창은 원본 `board.bmp`와 DLL의20픽셀 테두리 합성/짝수 경계 보정으로562×104를 생성했다. 원본 위치40,50,64픽셀 대사 초상과 비트맵 글꼴을 사용하며 별도 임시 ‘다음’ 버튼 대신 대화 영역 클릭을 받는다.
- 원본 지시 HP·MP·마법·기술은 **실습 캐릭터 상태에만 적용**한다. `CHARABILITY`의 원본 능력표 복사와 `HPSET` 절대값을 반영했다. 반지 지급 대사는 보존하되 식별자/지급 명령이 없는 반지 아이템을 만들거나 지급하지 않는다. `KILLCHAR1`의 제거와 `KILLCHAR2`의 시체 상태도 분리했다.
- 로그인/캐릭터/튜토리얼의 추가 요청 타입은 로컬 계약이다. 원작 wire opcode/패킹이 복원됐다는 뜻이 아니다. 제거한 싱글판 피해 공식·자연 AP 회복·보상·AI·월드 이동 규칙을 재활성화하지 않았다.

추가 정적 확인은 `Tools/MapChecks/original_tutorial_native_analysis.json`에 기록했다. 초기/후기 GameCtl의 F키 처리 주소는 각각0x10002F20/0x10002FB0으로 다르지만 확인한 창 번호/명시 위치는 같다. F6은 scene0 맵 정보, F12는 scene4 정보창 보기, F9는 scene28 도망 확인으로 기존 카탈로그 명칭도 정정했다. F7은 이 GameCtl 처리에서 기본 분기로 빠지며 상위 Saver 연결은 미확인이다. 후기 UserUnit 0x1000E9D0은 abilityrecord+8/+12/+16/+20을 HP/최대HP/MP/최대MP로 복사한다. 대본의 `SETHP`/`SETMP`는 초기·후기 명령 목록에 없으므로 `HPSET`/`MPSET` 별칭으로 임의 실행하지 않고 미적용 원문으로 기록한다.

이번 검증: 런타임(에디터 정의 포함)·Editor·NUnit소스 및 Player정의 런타임 API 컴파일 오류0. 생산 코드 연결 오프라인 검사**5,091건**, 그 안의 튜토리얼/신규 진입 검사**657건** 통과. 별도 원본 대본/그림/음악/맵301 빌드 등록 감사**231건** 통과. 테스트는 임시 저장 경로를 사용했으며 실제 계정/기존 실패 저장을 수정하지 않았다. **NUnit TestRunner와 실제 Unity Play는 실행하지 않았다.** 클라우드 Unity 라이선스가 없어 실제 실행 검증은 보류다.

남은 재현 범위: 이동 표시는 기존 분석의80ms 틱/직선16px×2·대각10px×3 단계를 재사용한다. 일반 원작 지형 경로 선택과 실제 재생 속도 대조는 미완료다. AP 최대치/그래프 시연, 사망 시체 애니메이션, 시전·피격·반격의 정확한 재생 순서, 일부 창의 동적 내용·F12 최초 위치·F7 상위 처리, 선행 대기실 이동 수업은 아직 원작 동일 판정 대상이 아니다. F2/F5/F6과 확인된 원본 창 틀·위치를 연결했지만 실제 화면·키/마우스·청음 전수 통과로 보고하지 않는다. 마을 자유 이동·일반 전투 등 미구현 서버 경계는 별도 작업이다.


### 다음 실제 Unity 검증 순서

1. 별도 신규 계정으로 가입→로그인→로컬 서버→10슬롯 중 빈 슬롯→파이터/나이트/매지션 생성. 계정 안내4페이지 대신 원본301 전투 실습에 들어가는지 확인한다.
2. 원본 대사를 클릭해 진행한 뒤 캐릭터 클릭→8방향 메뉴→이동→4,7 도착을 실제 마우스로 수행한다. 잘못된 타일/다음 클릭만으로 진행되지 않아야 한다. F2 실제 키·자기 캐릭터 가리키기·2,7/4,7 이동을 이어 확인한다.
3. 공격 선택→400 공격 두 번→휴식→101 파이어볼 선택/410 대상 선택→용병 직접 명령·001 선택·자동 방어를 실행한다. 실습 외 영구 HP/MP·마법·장비·골드가 바뀌면 안 된다. 원문 미등록 SETHP/SETMP의 별칭 보정은 하지 않는다.
4. F키 창 시연과 실제 F3·교관 동맹 체크, 교관 팔레트 변경, 전령 등장·마지막 대사→카오시아 복귀를 확인한다. 미구현 AP 그래프/시체 연출/창 내용은 원작 동일 통과로 세지 않는다.
5. 이동 후·마법 아이콘 선택 전/후·용병 이동 중 종료→동일 계정/캐릭터 재접속. 커서/실습 배치/하위 메뉴가 복원되고 완료 저장은 재생하지 않아야 한다. 실제 기존 저장은 사본으로만 검증한다.
6. 해상도/마우스 관통/중복 클릭/저장 실패/원본 BGM 청음·창 닫힘·마을 복귀 카메라와 전투 UI 잔존 여부를 확인한다. 80ms 틱을 연결했어도 실제 경로/재생 타이밍 통과로 세지 않는다.

## 원작 튜토리얼 검증 기준 정정 (2026-10-27)

원작 `TUTORIAL.DEO`는 이미 추출돼 있으며420명령·MESSAGE100개·맵301의 입력 대기/전투·메뉴 지시가 존재한다. 현재4단계 접속 안내를 원작 튜토리얼 통과로 계산하지 않는다. [재확인 내용](원작_복원_전환.md)을 기준으로 원본 명령 순서와 이동/공격/마법/휴식/용병/단축키/동맹 대기를 실제 조작과 연결해 검증해야 한다. 튜토리얼의 강제 HP/메뉴 값과 임시 마법을 일반 전투/영구 보상으로 적용하지 않는다. 반지 지급 ID는 대본에서 확인되지 않았다.

## 이전 기록 — 폐기된4페이지 안내 검증 (현행 대상 아님)

- 신규 임시 저장 경로에서 실행한다. 계정이 없으면 가입 화면이 열리고, 가입/로그인→로컬 서버 선택→10슬롯→빈 슬롯→3직업/이름→생성→튜토리얼 순서로 진행되는지 실제 Play 확인한다.
- 100/101/103 각각 캐릭터 이름·외형·카오시아21,21 위치를 확인한다. 기존 슬롯·백업·다른 계정 경로 요청은 거부되고 파일 해시가 유지되어야 한다.
- 안내 중 입력 잠금 및 다음/완료 클릭을 확인한다. 네 단계가 저장 성공 후 진행되고 같은 페이지 중복 클릭이 두 단계 진행을 만들지 않아야 한다.
- 1단계 진행 후 Play 종료/재로그인/서버·캐릭터 선택에서 이어지는지 확인한다. 완료 후 재선택에서 재생하지 않아야 하며 tutorial=null인 이전 저장도 강제 재생하면 안 된다.

## 훈련장 지속 전투 규칙 재검증 — 이전 단발 승패 기대를 대체

- 새 계정 또는 격리 사본으로101~107 훈련장에 입장한다. 기존 ‘몬스터1마리 처치→승리 결과창’ 또는 ‘사망→패배 확인→훈련맵’ 기대는 더 이상 사용하지 않는다.
- 훈련장 처치 후 결과창/자동 복귀 없이 전투맵에 남아야 한다. 캐릭터 사망 상태도 HP0을 유지하고 메뉴 접근/도망이 가능해야 한다. 사망 세부 원작 규칙은 확인 대기이므로 이 구현을 원작과 완전 동일하다고 통과 처리하지 않는다.
- **현재 respawnSeconds=0으로 미지정**이다. 실제 게임 리스폰이 작동한다고 통과 처리하지 않는다. 사용자 주기 확정 후 양수 값으로 설정해 처치 시각→지정 시간 직전/직후→재등장을 실측한다. 별도 fixture 임의 시간은 원작 시간 검증과 구분한다.
- 초기 칸 점유/이동 예약 중에는 리스폰이 지연되고 칸이 비워진 후 한 번만 생성돼야 한다. 새 개체의 HP/MP/AP·상태 효과·그림·좌표를 확인한다. 반복 처치에서 생명당 경험치 한 번, 중복 사망 통지·타이머 프레임에서 추가 지급 없음, XP 상한 실패 보존을 검사한다.
- ESC/전투 메뉴→도망→카오시아 훈련장 입구 앞(FromTraining) 직접 복귀·훈련/Battle 씬 해제·HP/XP/돈 보존·기존 최대MP 복귀 정책·저장/재접속을 실제 입력으로 확인한다. 결과 반영 실패 재시도와 마을 이동 실패 시 상태 보존도 분리한다.
- 일반 필드/시나리오 승리/패배·시나리오 개별 승리 결과 생략·종료 결과창은 기존 규칙대로 동작해야 한다.
- TrainingContinuousBattleTests 및 전체 관련 EditMode를 실행한다. 개발 소스 API 컴파일/오프라인 통합35,612개 통과는 실제 Unity 결과가 아니다. 이전 훈련장 패배 통과 기록은 과거 단발 구현에 대한 이력으로 남긴다.
