# 후기 버전 분석 기준 (2026-10-25)

## 기준과 우선순위

사용자 지시에 따라 이후 데이터 분석은 `saver/data1.cab`을 우선한다. 설치본 SHA-256은 `a6f518676a5530987c2f20309982d3df5f2bcafb10d0a5273c4ee4da258a21ea`다. 설치본의 정확한 배포 버전명은 미확정이다. PE 타임스탬프가 Saver.exe는 2004-03-17, GameCtl.dll·UserUnit.dll은 2003-03-12여서 기존 2000년 자료와 구분한다. 타임스탬프를 공식 배포일로 간주하지 않는다.

원문·해시·새 카탈로그는 `분석/Saver_Late/`가 기준이다. 이전 `Saver_1.2` 분석은 삭제하지 않고 버전별 근거로 보존한다. 동일 파일의 분석은 재사용하고 변경 파일의 수치·코드 주소는 후기 자료로 확인한다. 사용자 확정 초기 자금·회복·매입 등 싱글판 정책은 변경하지 않는다. 분석 기준 수립 뒤 확정 데이터의 Unity 적용을 진행했다. 최신 구현 범위와 미완료 이관은 `10_분석_적용_진행표.md`의 후기 데이터 Unity 적용 절을 따른다. 실제 Unity Play 검증은 아직 아니다.

## 맵·시나리오·보상

후기 설치본의 MRC **673개를 크기·타일·장식 구조까지 파싱**했으며 실패는 0개다. 시나리오 set 아카이브는 112묶음이다. 추가 33·330~333·404~406 아카이브와 기존 변경 302 이벤트, 변경된 필드/마을 맵은 파일·원문 카탈로그로 관리한다. MRC 구조 확인은 서버 배치·통행 정책·포털 연결 검증과 구분한다.

시나리오 33은 소개와 도입·종료 대본에서 야누스(직업 767), 종료 대상 인스턴스 700을 명시한다. CHARPOS·이동·삭제 명령은 시점별 연출일 수 있어 전체 출현을 동시 초기 배치로 합치지 않는다. 330~333·404~406의 간략 클리어 대본만으로 서버 지급 보상을 만들어 넣지 않는다.

**시나리오 01~17 set.arc는 기존 설치본과 바이트 단위로 동일**하다. 기존 명시적 보상 분석은 이 원문 범위에서 유지된다. 시나리오 10의 `GET_GENERAL` 표기는 그대로다. 이전 DLL에서 미지원임을 확인한 결과는 과거 버전 코드 근거이며 새 DLL에서도 동작이 같다고 검증한 것은 아니다. 후기 GameCtl.dll에도 GETGENERAL의 널 종료 문자열 1개가 있고 GET_GENERAL은 없음을 정적 대조했다(`reward_keyword_strings.json`). 이는 문자열 근거이며 실제 디스패치 실행이나 서버 전용 별칭을 확인한 것은 아니다. 후기 원문만으로 호크나이트를 보상으로 확정하지 않는다.

후기 클리어 보상 분석은 `clear_rewards.json`의 112묶음을 우선한다. 동일 아카이브 103묶음만 이전 원문 해석을 승계했으며 변경 302와 추가 8묶음은 별도 분류했다. 시나리오 10의 과거 클라이언트 실행 결과는 후기 결과로 승계하지 않았다.

`reward_commands.json`은 GETITEM·GETGENERAL·GOLD·FIRSTCLEAR·SCENECLEAR 등의 **원문 출현 목록**이다. 일반 상자·조건부 이벤트를 포함하므로 최초 클리어 보장 표로 대체하지 않는다. 기존 클리어 보상표는 01~17의 원문이 동일하다는 근거와 함께 사용할 수 있지만, 이전 바이너리 동작·전체 서버 송신 순서까지 후기에서 검증됐다는 뜻은 아니다.

튜토리얼은 MAP/tutorial.arc로 위치가 달라졌지만 기존 대본과 줄바꿈을 제외하면 같다. 행동 가속 반지를 준다는 대사는 있으나 명시적인 지급 ID가 없어 새 보상을 확정하지 않는다.

## 미확정 항목과 사용 제한

- `levelabl`의 163:35는 같은 값의 중복 행이다. 원문은 두 행 모두 보존한다. 45개 행은 17열이므로 18열로 강제 해석하지 않는다.
- 완전한 18열 성장 행의 마법/기술 참조 중 26종은 이번 magictbl에서 찾지 못했다. 빈 목록 토큰도 70개 있다. 상세 키·행 번호는 `source_quality.json`에 기록했다. 서버 전용 고용 규칙·오타·다른 테이블 처리 여부는 미확정이며 가짜 기술을 추가하지 않는다.
- `ability_bak.at`·`levelabl_bak.a`는 디코더 EOF로 복원하지 못했다. 현행 주요 ATR과 구분하며 기준값으로 사용하지 않는다.
- 후기 버전에서 해시가 달라진 GameCtl/UserUnit/SetUnit/Saver 등은 기존 디스어셈블 주소·호출 규약·필드 해석을 자동 승계하지 않는다. `executables.json`의 파일 해시로 구분한다. 원본 게임·서버·Unity Play는 이번에 실행하지 않았다.
- 로그인 이미지와 UI 배치 파일은 후기 원본 후보를 확보한 상태다. 버튼 동작·입력·그래픽 재생·타이밍을 확인한 것으로 보고하지 않는다.
- 현재 Unity의 직업 범위 100~169, 70직업 검증 집계, 이전 아이템·기술·성장 데이터는 후기 전체 지원의 증거가 아니다. 후기 적용 시 170~172·169 외형·성장·수치·효과 누락을 검토해야 하며 이번 분석 변경만으로 구현 완료 처리하지 않는다.

## 재현·확인

`분석/Saver_Late/README.md`의 명령으로 모든 카탈로그를 재생성한다. 원본 파일 SHA256 대조, 시나리오 01~17 동일성, 주요 행·복합 키·중복 보존, 마법 참조, 맵 파싱 결과를 확인했으며 `verification.json`에 남겼다. 기존 저장 데이터는 수정하지 않았다.


## 구현 대조에서 추가 확인한 원본 차이

- 후기1000은61×61,1002는65×65다. 기존 Unity 맵과 단순 교체하면 출입구·NPC·스폰 연결이 달라진다. 필드1010의 기존 스폰(23,34)은 후기에서 지형9다. 후속 작업에서 세 맵의 지형과 싱글판 출입구를 이관했다. 구현/검증 범위는 진행표 최신 절을 따른다. 원작 서버의 출입구 복원을 뜻하지 않는다.
- 그랜드소드170의 BMP 팔레트는218개다. 기존 관계색3 변환에 필요한 일부 인덱스가 없으므로 동맹색을 추정 생성하지 않았다. 171/172는 정상 변환 가능하다.
- 후기 face.arc에는100~169의70개 얼굴이 있고170~172는 없다. 원본 없는 얼굴 대신 기존 NoFace를 사용한다. 본체 스프라이트는 세 신규 직업 모두 존재한다.
- Item.bmp는255색 팔레트와1074 픽셀 오프셋을 사용한다. 256색/1078 오프셋 고정 가정은 후기 자료에 맞지 않는다.
- MIDI 표의 헤더는47이나 실제 ID/파일 쌍은50개다. 현용 지역1002/1003/1004/1012의 명시적 연결은game9/game10/game3/game12다. 1011·1060·1070·1080·1090·1110과1110을 상속하던1111에는 후기 명시 연결이 없어 기존 BGM을 버전 예외로 유지했다. 이를 후기 원본의 확정 연결로 보고하지 않는다.

- 후기 Fx.bmp는999×1098로 확장됐고 기존999×999 영역에서도 픽셀이 달라졌다. 확인된 기존 프레임의 원본 사각형에만 후기 픽셀을 반영했다. 런타임 지연·반복·깊이 규칙이나 미정의 패턴64/65를 새로 추정한 것은 아니다.
