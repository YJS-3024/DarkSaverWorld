# 원작 튜토리얼 분석 기준

이 문서는 초기판·후기 설치본의 원작 증거를 기준으로 한다. 현재 Unity 구현이나 사용자 기억을 원작 동작의 증거로 사용하지 않는다. 범위는 튜토리얼의 자료 원본,420명령 전체,진입·대기·종료,입력·창·유닛·그림·음향 연결,후기 Saver.exe에서 복구한 선행 대기실 수업이다. 원본 프로세스의 실제 화면/청음 실측은 수행하지 않았다. 아래의 주소·카운터·파일 시간은 정적 분석 결과다.

## 원본 파일과 동일성

- gameres/tutorial.arc와 map/tutorial.arc는 각각 TUTORIAL.DEO 하나를 포함하며 압축 해제한 CP949 바이트가 동일하다:14146bytes,SHA256 `411b5d750b6aa8a0b0b325deba181fb99b6ce53f2d74736e0b09801f1e8a236c`.
- UTF8 변환 후 CR 제거 해시는 `eb5216f5c0cf3b6a6b3a61cbd3f70876b1e4ed5997295924a2d9fbe5070e715d`. 초기판과 후기판의 원문 행도 동일하다.
- 원문443행 중 실행 목록420개,대사100개,명령44종. 전체 실행 순서·대사는 `분석/Saver_Late/tutorial_command_sequence.csv` 및 JSON에 보존한다.
- 별도의 선행 수업은 이 두 ARC에 없다. **후기 Saver.exe의 RT_STRING61216~61251에서 대기실 수업36개를 복구했다.** ARC만 검색하거나 CP949 문자열만 찾았던 기존 조사에서 누락했다. 맵1500과 Wlib 화면을 사용하는 선행 수업은 맵301 전투 대본과 구분하며, 상세 근거는 마지막 절을 따른다.

## 진입부터 종료까지

1. GameCtl의 스크립트 로더1000FAB0은 아카이브 관리자가 유효할 때 진행한다.1000FAFD의 튜토리얼 플래그가0이 아니면1000FDEE의 Map/tutorial.arc와 tutorial.deo 경로를 사용한다.
2. 빈 원문은1000FE64의 정리 분기로 나간다. 로드 성공 시999행 상한의 문자열 배열을 채우고 실행 종류2·활성1·커서0을 설정한다.
3. 대본은 맵301→nco01.mid→시점10,7→튜토리얼 입력 제어→초기4유닛 배치로 시작한다.
4. 실제 흐름은 원문의 순서대로 행동 메뉴·이동·공격·휴식·마법·상태창·동맹·지휘·창과 단축키 설명을 진행한다. 대본의 대사와 수치를 일반 전투 규칙으로 재해석하지 않는다.
5. 후속201 유닛2개와805 유닛1개를 배치하는 원문도 동일420명령에 포함된다.805의 이동 뒤 WAITFORMOVEEND는 전용 분기가 없는 표기다.
6. ENDGAME과 END는 서로 다른 종료 처리를 실행한다. 원문 이후 마을 위치·초기 돈·계정 저장을 이 대본의 기능으로 추가하지 않는다.

## 입력과 시간

공통 대기는 context+20으로 활성 여부,+24로 종류,+28로 시작 clock,+2C로 대상을 보관한다. 숫자 대기는 clock 차이 비교,-3은 입력 완료 플래그,-2는 이동 bit0 해제다. 커서는 명령 실행 전에 증가한다. WAITMOVEPOS의 클릭 완료와 DO2의 실제 이동 종료는 같은 조건이 아니다.

WAITMOUSEMOVE는10002DC3에서 칸의 유닛을 찾고10002DF4에서 ID를 비교한다. “마우스 이동만으로 완료”라는 이전 기록은 잘못된 것으로 폐기한다. Unity는 sprite 사각형을 검사하므로 경계 픽셀까지 같다는 실행 증거는 없다.

원본 아이콘 설명에는 마스크→DO500→마스크0→DO500→마스크 복원의 점멸이 있다. 이전 사용자 요청으로 Unity가 직전 마스크를 유지하도록 바꾼 부분은 원작 차이이며 원문을 고치지 않는다.

UserUnit의 갱신 게이트는80 clock틱.500초과 지연은 누적을 버리며 한 호출에 한 단계만 진행한다. 별도 그림 선택에는100/250틱2상,125틱3상,125/333틱0→1→2→1 선택이 있다. DO500의 다음 Update 검사와 실제 Sleep500 호출을 동일한 처리로 구현하지 않는다. Saver의10ms 타이머는 KEYPRESS 비교 후 종료 메시지 경로이며 화면100fps 근거가 아니다.

맵301은20×15칸·장식31개이며 자원 ID105/1/101/0/2를 가진다.301.mrc·301t.mrc·301hmap.bmp와 mdsr105/1/101/0/2.grs의 원본 해시를 대조했다. 자원ID0의 존재만으로 의미를 부여하지 않는다.

## 창과 표시

F1은scene7,F2는1,F3는3,F4는5,F5는24~27,F6는0,F8은6,F9는28,F12는4로 연결된다. SHOW/HIDE는 공통 F키 토글이다. GameCtl의F7은 기본 분기이며 원문에 전체 사용자 안내가 있다는 이유로 그 함수 안에 별도 창 구현이 있다고 만들지 않는다. Glib32개 레이아웃은 관련 후보 전체 목록이고 실제 사용 화면 수가 아니다.

클릭은 누른 컨트롤의 사각형 안에서 해제했을 때 배열 순번으로 전달된다. hover는 임시 상태2를 그린 뒤 기본1로 되돌린다. 창의 마우스·키보드·반복 콜백은 분리되어 있다. 전투 클릭34경우와 누르고 있기3그룹의 주소·경계는 native_ui_timing_audit.json에 보존한다. 공통 튜토리얼 억제는 첫 닫기/최소화 요청을 소비할 수 있다. 창 위치 요청은 튜토리얼 밖에서8/12/28 외에는 거부된다.

## 공격·마법·사망·음향

일반 공격은 공격자와 대상의0x04 상태를 시작한다. 독립적인 반격 계산을 추가하지 않는다. 공격 카운터48초과에서 종료하고 효과 프레임은(counter/2)%4 경로다. 마법101은 magictbl의패턴2를 참조한다. 이동 구간0~9,착탄10 이후라는 카운터 조건과 음향 호출 순서를 사용하며 이10을10초로 바꾸지 않는다.

마법 효과 확인 경로는 시작 때Sound2가 양수이면 재생,착탄 분기에서Sound2 정지 후Sound1이 양수이면 재생이다. 상태 교체·대상 제거와 프레임 건너뛰기 때의 동작까지 임의 보간하지 않는다. KILLCHAR2의0x80 상태는0x40 효과와 우선순위로 시체 표시 시점을 달리한다. KILLCHAR1은 즉시 제거 경로다.

soundll은 sound.arc의00.wav~99.wav를100슬롯으로 로드한다. 없는 파일은0슬롯이다. 재생/정지 API는0슬롯을 무시하나 ID 범위 검사는 없다. 같은 ID는 같은 DirectSound 버퍼를0위치로 돌려 Play flags0으로 재생한다. 복제 버퍼 큐가 아니다. SetSound는 새 재생 허용값을 바꾸며 재생 중 버퍼를 순회 정지하지 않는다. StopSound는 허용값과 무관하게 해당 버퍼를 멈춘다.

DirectMusic 공개 Play는 기존 StopSegment→ReleasePort→CreateAndAddPort→AttemptFileOpen 순서다. 실패하면 기존 곡이 유지되는 구조가 아니다. 성공하면 PlaySegment(1),SetRepeats(1000) 경로이며 공개 int 인수는 이 본문에서 읽지 않는다. Pause는 위치를 보존하고 Stop은0으로 초기화한다. 특정 알림GUID와옵션1이면Stop을 호출하며 이벤트 처리기 자체에는 자동 재시작이 없다.

Nco01.mid는 후기 manifest와 동일하다. format0·1트랙·480틱/4분음표·tempo937500µs·종료26880틱으로,파일 템포 기준 한 회52.5초다. 이는 신시사이저·장치 지연과 실제 청음 실측을 포함하지 않는다.
