# 원본 몬스터 배치 도구

## 오른쪽 메뉴 너비 조절 (2026-11-01)

오른쪽 메뉴의 **왼쪽 세로 경계**를 드래그하면 너비를 조절한다. 경계를 두 번 클릭하면 기본 너비로 복원하고, 드래그 중Esc는 조절 전 너비로 취소한다. 너비는 편집기 개인 설정에 저장해 다음 실행에도 복원하며 맵/입구 저장 파일은 변경하지 않는다. 창 크기에 따라 지도 공간을 남기는 범위에서 조절할 수 있다. 지도가 좁아지면 추가 버튼을 다음 줄로 옮겨 탭/오른쪽 메뉴와 겹치지 않게 표시한다.

Runtime/Editor/Player API 오류0·경고0과 입구289개·캠페인464개 회귀를 확인했다. 실제 Unity 창에서 경계 드래그·더블클릭·Esc·너비 복원·축소된 지도 조작을 확인하는 검증은 미실행이다.

## 사용자 입구 목록 그룹화·순서 편집 (2026-11-01)

**맵 입구 연결 → 사용자 입구 목록**에서 **그룹화 없음 / 출발 맵 / 도착 맵 / 사용자 그룹**을 선택한다. 그룹 제목으로 접기/펼치기가 가능하며 검색은 이름·맵 번호/이름·사용자 그룹명에 적용한다. 검색 결과를 줄여도 숨겨진 입구는 삭제하지 않는다.

- **사용자 그룹:** 입구를 선택하고 아래 **사용자 그룹**에서 기존 그룹을 고르거나 **그룹명 직접 입력**으로 새 이름을 지정한다. 미지정 항목은 별도 그룹으로 표시한다. 사용자 그룹 보기에서는 항목을 다른 그룹 제목/행으로 드래그해 그룹을 옮길 수 있고, 그룹 제목의↑↓로 그룹 순서를 바꾼다.
- **사용자 순서:** 행 왼쪽 **≡**을 드래그하거나↑↓로 순서를 바꾼다. 출발/도착 맵 그룹에서는 같은 그룹 안에서 순서를 바꾸며, 다른 맵 그룹으로 드래그해 실제 연결 맵 번호를 바꾸지는 않는다. 그룹화 없음을 선택하면 전체 목록에서 순서를 지정할 수 있다.
- **자동 정렬:** 이름순·출발 맵순·도착 맵순은 우선 보기 순서다. **현재 정렬을 저장 순서에 반영**을 누르면 검색/접힘으로 숨긴 항목까지 포함해 문서 순서를 바꾸고 사용자 순서로 전환한다. 자동 정렬을 보는 동안 드래그/↑↓는 비활성이다.
- **저장:** 변경 후 **입구 연결 저장**을 누른다. 사용자 그룹은 각 입구의 선택적 `group`, 수동 순서는 `gates` 배열 순서에 저장된다. 기존 파일은 그룹 미지정으로 읽고 기존 순서를 유지한다. 되돌리기/다시 실행과 파일 외부 변경 충돌 검사는 기존대로 적용한다. 보기 그룹화·검색·정렬 방식은 편집창 상태이며 연결 패킷/좌표를 바꾸는 설정이 아니다.

입구 관리형289개·기존 캠페인464개와 Runtime/Editor/Player API 오류0·경고0 통과. 그룹명·임의 순서의 실제 파일 저장/복원과 연결 정보 보존을 확인했다. 실제 Unity 창의 마우스 드래그·접기/펼치기 검증은 미실행이다.

## 여러 칸 입구·다른 맵 도착 설정 (2026-11-01)

**DarkSaver → 원작 도구 → 시나리오 편집툴 → 맵 입구 연결** 탭에서 편집한다. 기존 NPC 연결도 이 탭에 그대로 남는다. 한 맵에 여러 입구, 같은 목적지로 향하는 여러 입구를 저장할 수 있다. 사용자 연결은 원본 복원값과 구별하며 `UserGateways.json` 기본값 `gates=[]/applyToGame=false`를 자동 변경하지 않는다.

1. 왼쪽에서 출발 맵을 선택하고 **이 맵에 이동 입구 추가**를 누른다. 건물·마을·필드 출입구는 이동 입구, 클릭 후 방 참가가 필요한 시나리오 NPC는 **이 맵에 NPC 입구 추가**를 사용한다.
2. 이동 입구는 **가로/세로 칸 수**를 입력하거나 **3칸 × 1 / 6칸 × 1**을 누른다. **출발 맵에서 입구 영역 그리기** 후 지도에 클릭하면 현재 크기로 배치하고, 드래그하면 양 끝 타일을 포함한 사각형으로 지정한다. 배치된 영역을 드래그하면 크기를 유지하며 이동한다. 좌표는 영역의 좌상단이다.
3. **도착 맵**에서 마을·실내·필드·시나리오 중 다른 맵을 선택한다. **도착 가로/세로 칸 수**로 도착 출구 크기를 지정하거나 **도착2×1 / 도착1×2**를 누른다. **도착 맵에서 출구 영역 그리기**로 해당 지도를 열어 클릭하면 현재 크기로 놓고, 드래그하면 사각 영역을 그린다. 놓인 도착 영역도 드래그 이동할 수 있다. **출발 지도 보기 / 도착 지도 보기**로 두 맵을 오가며 이름·크기·출발 맵이 적힌 초록색 도착 영역을 확인한다.
4. 기존 출입구는 지도 테두리와 오른쪽 **기존 출입구** 목록에 표시한다. 선택 후 **이 출입구를 편집본으로 가져오기**를 누르면 원본 영역·목적지·도착 좌표를 복사해 수정한다. 명시적 수정본만 기존 출입구를 대체한다. 수정본을 끄거나 삭제하고 적용하면 원래 출입구가 복원된다. 원본 맵/카탈로그는 수정하지 않는다.
5. **이 연결 사용**, **저장한 연결을 로컬 서버에서 사용**을 켜고 **입구 연결 저장**을 누른다. 다음 Play/프로필 진입부터 로컬 서버의 기존 이동 요청/응답 경로를 사용한다. 돌아오는 출입구는 반대 방향으로 따로 추가해야 한다. 수련장 입구는 카오시아 복귀 좌표도 지정하며, 같은 수련장에 여러 입구가 있어도 실제 이용한 입구의 복귀 칸을 사용한다.

출발 영역 중첩·맵 밖·막힌 이동 칸·직원/원본 몬스터 충돌을 적용 시 거부한다. 도착 영역도 모든 칸의 지형·직원·원본 몬스터를 확인한다. 도착 출구가 반대편 입구와 겹치는 것은 허용하되, 해당 출구를 완전히 벗어나 다시 들어와야 이동을 요청할 수 있다. 도착 직후 영역 안에서 한 칸 움직이거나 재접속해도 바로 되돌아가지 않는다. 실패한 적용은 일부 입구만 반영하지 않으며, 맵 이동 저장 실패 시 출발 상태와 진입 대기를 보존해 재시도한다. 기존 버전1 파일은 도착 크기 필드가 없으면1×1로 읽는다. 저장 파일 외부 변경 방지와 되돌리기/다시 실행은 유지한다.

다중 도착 칸 선택은 원작 서버 판정으로 확인된 규칙이 아닌 **로컬 편집 연결 규칙**이다. 출발/도착 영역을 위에서 아래, 각 행은 왼쪽부터 순서대로 대응한다. 칸 수가 다르면 진입한 칸의 순서를 비례 배분한다. 예를 들어6×1→2×1은 앞3칸이 첫 도착 칸, 뒤3칸이 두 번째 도착 칸이다. 가로↔세로 연결도 같은 순서를 쓰며, 출발이 한 칸인 NPC 입구는 첫 도착 칸을 사용한다. 돌아오는 방향의 입구는 별도 설정한다.

검사 명령은 `python Tools/OriginalWorldChecks/check_gateways.py`, 결과는 `Tools/OriginalWorldChecks/gateway-check.json`이다. 입구 관리형289개·기존 캠페인464개, Runtime/Editor/Player API 오류0·경고0을 확인했다. 출발3×1·6×1·1×3·2×3과 도착2×1·1×2·2×2, 가로↔세로 연결·왕복·출구 내 보행/재접속·수정본 해제·저장 실패 재시도·그룹/목록 순서 저장을 포함한다. 실제 Unity 창의 마우스 조작/Play 확인은 미실행이다.

## NPC 입구 연결 추가 (2026-10-31)

5. 저장 파일은 `Assets/_Original/Data/Campaign/UserGateways.json`이며 원본/몬스터 배치와 분리한다. 변경은 다음 Play/프로필 진입부터 적용된다. 기존 계정/저장을 직접 수정하지 않는다. 현재 저장된 캐릭터 위치와 NPC가 겹치면 임의 위치로 옮기거나 덮어쓰지 않고 진입을 거부하므로 NPC 위치를 수정한다.
6. 게임에서는 NPC 옆으로 이동해 클릭→원본 Wlib11 그림/버튼의 방 목록→로컬 방 선택→참가 순서다. 밟기 자동 입장은 없다. Escape/우클릭으로 취소하고 같은 맵에 남는다. 여기의 로컬 방1개는 연결 검증용 서버 구현이며 원작 방 개수/생성 규칙·온라인 플레이를 복구했다는 뜻은 아니다.

## 초기화 전 도구 기록 — 현재 실행 명령 아님

아래 `_Game` 경로의 생성기/검사는 초기화 전 구현 기록이다. 현재 프로젝트에 실행해 이전 코드나 배치를 다시 생성하지 않는다. 새 편집툴의 실행/검사는 위 메뉴와 명령을 따른다.

```bash
python Tools/ScenarioPlacementChecks/build_original_editor_layouts.py
python Tools/ScenarioPlacementChecks/apply_original_deployments.py --apply
python Tools/ScenarioPlacementChecks/check_editor_troops.py
```

- 첫 명령: 원문 SET/POS16맵/610몬스터·195아군 슬롯을 `Assets/_Game/Resources/Scenarios/Original/{id}/Deployment.json`으로 생성한다.61직업/36직그림의 첫 하향 프레임과 편집툴 색인을 만든다. 편집한 배치는 보호하며 `--reset`은 명시적인 원문 복구다. Pillow/PyYAML 및 설치본 추출 인벤토리가 필요하다.
- 두 번째 명령: 기존 Content의 보완 편성을 제거하고 원문이 없으면 `original-missing`과 빈 배열을 기록한다. 대본·이벤트·진입/지형은 보존하며 콘텐츠/비주얼 해시와 현용 목록을 동기화한다. --apply가 없으면 변경 미리보기만 한다. 반복 실행해도 새로운 몬스터/보상이 생기지 않는다.
- 마지막 명령: Unity의 .NET SDK/API로 실제 Runtime+변경 Editor를 컴파일하고 생산 해석기/유닛 타입을 관리형으로 검사한다. 원문 위치, 공용 리소스 검증, 빈 편성 초기화 거부와 미확정 데이터 차단을 확인한다. Unity가 다른 경로에 있으면 `--unity-data <Editor/Data>`를 지정한다.
