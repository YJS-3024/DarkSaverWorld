# F2·F3·클래스정보 로컬 서버 연결 — 2026-10-29

이전 world-functions 구현 이후의 추가 변경이다. 기존 실패 저장이나 계정 파일을 이 작업에서 변경하지 않았다. 원작 서버 전체를 복원한 결과가 아니다.

## 반영

- ServerManager.WorldCharacters / WorldCharacterService: 요청별 단일 서버 핸들러, 조회·출전0x42·순서0x3B·능력 조회0x86·비용0x8A/8B·후보0x87·능력치0x82·마법0x83/84/85·전직0x81·확인/취소0x88/89 처리 경계.
- F2/F3/F4를 열 때 로컬 서버에서 보유 캐릭터 스냅샷을 새로 받는다. 소유하지 않은 레코드·없는 슬롯·슬롯0 토글·현재 맵 사용 불가 상태는 거부한다. 슬롯0 제외는 원작0x41C960의 순번 규칙이다. 레코드ID100을 무조건 토글 금지하는 것으로 오해하지 않는다.
- 출전 원시값과 칸 순서를 NativeSaveData.worldCharacters에 계정별로 저장·복원한다. 저장 실패 시 메모리 설정과 클라이언트 수신값을 바꾸지 않는다. 저장은 동일 dispatcher 안에서 중첩 SaveWorld 요청을 만들지 않고 기존 저장 실행부를 사용한다.
- 원작 raw2→첫 그림,raw1→두 번째 그림에 맞춰 F2 토글 그림 연결을 수정했다. 사용자 확인에 따라 두 번째 밝은 상태를 출전 선택으로 취급한다. 기존 미지정 계정에 출전값을 소급 저장하지 않으며 최초 클릭은raw1 요청이다.
- F3 능력 정보724바이트,6개 비용,클래스 후보 원본 데이터를 서버에 등록할 수 있다. 원본 데이터가 등록된 캐릭터의 조회에만 해당 정보를 알린다. UI는0x87 후보 응답을 직업 카탈로그와 연결하며 현재 클래스 그림도 선택한 캐릭터 기준이다.
- 원본 비용이 등록된 경우 기존 OriginalCharacterInfoValues의 확인된 포인트 증감 처리를 서버에서 재검사한다. 임시 변경은 확인 전 저장하지 않고 취소 시 폐기한다. 확인 저장 실패 시 원본 저장은 보존하며 재시도 가능하다. 열린 뒤 원본 정보가 바뀌면 재조회가 필요하다. 동시에 변경한 출전 플래그를 능력치 확인으로 덮어쓰지 않는다.
- 마법·전직 변경은 ConfigureLocalWorldCharacterPolicy에 등록된 검증 규칙에만 위임한다. 규칙 없이 성공·마법 지급·직업 변경·포인트 지급을 만들지 않는다. 마법 목록0x83/85도 원본 바이트 왕복 처리에 포함했다.
- 등록 충돌 시 이번에 설치한 핸들러만 해제하며 기존 소유자를 보존한다. UI 비활성/로그아웃 시 편집 상태와 소유한 핸들러를 정리한다.

## 서버 데이터 공급 API

`ServerManager.InstallVerifiedWorldCharacterData(WorldCharacterData[])`는 신뢰하는 서버 설정용 API다. 클라이언트 패킷으로 임의 원본 데이터를 설치하는 기능이 아니다. RecordId별 Flag(0미지정/1·2원본), Info(724바이트), StatCosts(6word), ClassOptions(원본0x87 바이트)를 공급한다. 부분 데이터가 없는 항목은 새로 만들지 않는다. 현재 세션의 실제 보유 캐릭터만 허용하며 저장이 성공해야 적용된다.

`ConfigureLocalWorldCharacterPolicy`의 콜백은 원본 규칙에 따른 후보 데이터만 반환하는 순수 변환이어야 한다. 실제 세션을 저장 전 직접 변경하면 안 된다. 성공인데 결과 레코드가 없거나 다른 캐릭터 결과이면 거부한다.

## 완료로 세지 않는 범위

- 기존 저장에는 원본 능력 포인트·비용·후보가 없으므로 자동으로 생성하지 않았다. 데이터 미등록 상태의 능력 편집은 거부될 수 있다.
- 전직 자격·비용·마법 편성 변경의 최종 원작 서버 규칙은 여전히 미등록이며 기본적으로 거부한다.
- 능력치의 저장/알림 대상은 원본 정보 레코드다. 이를 실제 전투의 유효 능력치로 환산하는 서버 계산까지 완료한 것으로 보지 않는다.
- F2 출전 선택의 저장과 시나리오 입장 시 실제 선발·인원 제한 적용은 별개다. 이번 작업으로 입장 선발 경로를 완료 처리하지 않는다.
- 기존 F4 장비 승인과 F12 이동 목적지 규칙은 본 작업 범위가 아니다.

## 검사

- Unity6000.5.7f1 API 참조 Runtime/Editor/Tests/Player 컴파일 오류0.
- 직접 관리형16개 통과(기존 패킷8+새 서비스8). 실제 Unity TestRunner가 아니다. 출전/순서 저장 후 수신, 저장 거부·미소유·비활성 거부, 원본 비용/후보 알림, 미확정 규칙 거부, 정책 결과 검증, 능력 임시변경·환불·취소·확인 실패 재시도, 동시 출전 설정 보존을 검사했다.
- 기존 오프라인 통합5840검사 통과. 새8항목은 별도 임시 파일에 선택 서버 데이터의 저장·복원·복사 독립·잘못된 저장 거부를 확인한다. 이 JSON 어댑터 결과는 실제 Unity JsonUtility 결과가 아니다.
- Unity 통합 검사는 컴파일만 확인했다. 기존 선택창 fixture를 실제 서버 응답 방식으로 바꾸고, 핸들러 등록 충돌 롤백/원본 요청 프레이밍/수신 순서/해제를 검사하는 새 사례를 추가했다.
- 라이선스 제약으로 실제 Editor 임포트·TestRunner·Play는 미실행이다.

## 실제 Unity 후속 검증

1. 별도 저장본으로 보유 캐릭터2명 이상 상태에서 F2 토글·순서 변경→Play 재시작→동일 계정 복원. 다른 계정에는 영향이 없어야 한다.
2. 저장 불가능한 별도 경로로 요청하여 거부 후 체크·순서·기존 파일 보존 확인. 실제 캐릭터 저장·주 캐릭터가 선택에 따라 교체되지 않아야 한다.
3. 검증된 원본 데이터가 등록된 별도 fixture에서 F3→능력창 조회→비용·클래스 후보 수신→증감·취소/확인. 비용 없는 fixture에서는 변경 거부 확인.
4. 능력 임시변경 중 F2 출전 설정 변경 후 확인하여 새 출전값 보존 확인.
5. 전직/마법 규칙 미등록 거부와 별도 등록한 규칙의 응답 경로를 구분한다. 이것을 원작 자격 공식 검증으로 세지 않는다.
6. 실제 시나리오 입장 선발·전투 유효 능력치는 아직 별도로 연결/검증해야 한다.
