# 원작 전직 UI 기능 연결 (2026-10-30)

## 근거

기존 원본 능력조정 패널 `Wlib/scene23.lsc`(내부 창ID40)과 클래스 후보87/변경81을 재사용했다. 별도 NPC 전직 창을 창작하거나 이전 싱글판 전직 미리보기/레벨업 함수를 다시 열지 않았다. 확인된 경로는 F3 자기정보→능력조정→클래스 영역이며 모든 전직이 NPC 없이만 가능했다고 원작 전체를 단정하는 근거는 아니다.

구형 Saver.exe `0x41A700~0x41A7C7`를 GNU objdump로 재확인했다. info+0x3A WORD가0이면 요청을 하지 않으며 수신된 후보 유효 상태+0xF8도 확인한다. slot0은+0xEC,slot1은+0xE8,slot2는+0x100의 현재 후보를 읽어81+정보레코드WORD+클래스WORD를 보낸다. 이후+0x3A를 감소시키고0x41A210(86재조회)을 호출한다. 근거 명령은 `ds-class-ui.asm`에 보관했다.

## 변경

- 기존 scene23 클래스 아이콘/이름/설명,좌우2칸과 하단 후보,이전/다음 선택을 유지했다. 기존 UI가 없었던 것이 아니라 일부 연결돼 있던 상태였다.
- 공용 OriginalClassChangeSelection에서 원본 포인트WORD·후보 존재·slot·인덱스·-1빈 후보를 검사하고81요청을 만든다. 클라이언트 선택이 저장된 직업·레벨·능력치를 바꾸지 않는다.
- UI 변경 버튼을 공개 RequestOriginalClassChange로 연결했다. 원본 포인트 미수신/0,미선택,현재 요청 대기 시 비활성이다. 유효 요청 뒤86재조회를 보내고87이 다시 오면 대기를 해제한다. 거부 시 기존 오류 표시와 함께 재요청 가능 상태로 돌아간다. 창 닫기 시 대기를 해제한다.
- 원본의 즉시 포인트 감소는 서버 정보 원본에 직접 적용하지 않았다. 이 구현은 새 후보를 받을 때까지 중복을 막고 확정 정보 재수신을 사용한다. 원작과 내부 메모리 변경 시점까지 완전 동일하다고 표기하지 않는다.
- 서버 전직 조건/포인트 비용 계산/직업 적용/성장/저장은 이번 범위 밖이다. WorldCharacterService.AdjustmentPolicy 미등록 시 기존처럼 거부한다. 거부를 전직 성공으로 표시하지 않는다.

## 검증

Runtime/Editor/Tests/Player 보조 API컴파일 오류0. 실제 생산 타입 관리형 직접 검사18개 통과(새 선택/포인트/경계/wire2개와 기존 월드 프로토콜·서비스16개). 코드 공백 검사 통과. 실제 Unity 임포트/TestRunner/Play는 라이선스 제약으로 미실행.

별도 계정/저장으로 F3→능력조정을 열어87없음/포인트0시 변경 비활성,좌우·하단 후보 선택/설명/이전·다음 경계,81레코드와선택값→86순서,응답 전 중복 차단,87갱신 후 재선택,거부시 상태 보존·오류 표시,확인/취소/닫기와 입력 복구를 실제 Unity에서 확인해야 한다. 원본 후보·포인트 응답을 주는 별도 fixture는 전직 서버 판정 성공으로 세지 않는다.
