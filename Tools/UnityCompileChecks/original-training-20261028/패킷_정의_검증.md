# 훈련장 로컬 패킷 정의와 등록

2026-10-28 KST. 원작 미확정 서버 규칙을 채우지 않고, ServerManager에 훈련장 전용 패킷과 처리기 등록 API를 추가했다. 이 문서는 기존 원작 대조·훈련장 코드 정리 기록의 후속이다.

## 패킷

| 방향 | 형식 | 데이터/역할 |
| --- | --- | --- |
| 요청 | Request_EnterTraining | 훈련장 진입 요청. 직업·목적 맵·적 편성을 클라이언트가 결정해 보내지 않음 |
| 응답 | Response_EnterTraining | 승인/거부·이유, 승인된 세션ID·맵101~107·진입 타일좌표 |
| 요청 | Request_ReadyTraining | 세션ID·목적지 로딩 성공 여부 |
| 응답 | Response_ReadyTraining | 해당 세션의 준비 승인/거부·이유 |
| 요청 | Request_GetTrainingState | 세션ID로 초기/재동기화 상태 조회 |
| 응답 | Response_GetTrainingState | 승인/거부·이유, 세션ID·맵ID·리비전·명시적 개체 상태 목록 |
| 서버 알림 | Notify_TrainingUnits | 세션ID·리비전·Initial/Spawn/Respawn 구분·명시적 개체 상태 목록 |
| 요청 | Request_RetreatTraining | 현재 세션의 도주 요청. 클라이언트가 복귀 위치를 결정하지 않음 |
| 응답 | Response_RetreatTraining | 승인/거부·이유, 승인된 세션ID·복귀 맵/런타임·좌표 |

이는 **로컬 연결용 계약**이다. 원작 전용 opcode·필드 배치·세션ID/리비전 wire 형식을 복원했다고 주장하지 않는다. OriginalLocalPacketCodec에는 임의 opcode를 추가하지 않았다. 맵20×15 범위는 원본 훈련장 리소스에 맞춰 검사한다.

HP/MP/XP·AP/메뉴·사망/제거·공격/마법 결과는 기존 HpSetNotification / MpSetNotification / ExperienceSetNotification / TickMenuNotification / UnitCorpseNotification / UnitRemoveNotification / AttackEffectNotification / MagicEffectNotification을 계속 사용한다. 처치 요청을 곧바로 경험치 지급으로 바꾸거나 Respawn 알림만으로 비용·보상·회복을 계산하지 않는다. 클라이언트가 재등장 시간을 지시하는 요청은 만들지 않았다.

## ServerManager 연결

```csharp
// 연결할 규칙이 없으면 형식별 거부 응답만 반환한다.
server.BindLocalTrainingService();
server.TryRequest(new Request_EnterTraining(), out var response);

// 명시적 서버 권한 구현을 연결할 때:
server.UnbindLocalTrainingService();
server.BindLocalTrainingService(authority); // ITrainingServerAuthority

// 권한 구현이 확정한 생성/재등장 데이터를 서버에서 클라이언트로 전송:
server.SendToClient(new Notify_TrainingUnits(sessionId, revision, kind, units));
```

- 기존 LocalServerDispatcher·TryRequest·ResponseReceived 경로를 사용한다. 건물 MapEnter 처리기와는 다른 요청 타입으로 등록한다.
- ITrainingServerAuthority가 Enter/Ready/State/Retreat를 처리한다. 인증·선택 캐릭터·거리·현재 세션 소유권·로드 상태·리비전 순서·재등장 규칙·도주 승인은 이 권한 구현이 판단해야 한다. 이번에 그것을 자동 제공하지 않았다.
- 처리 규칙을 연결하지 않거나 결과가 null이면 명시적인 형식별 거부 응답을 반환한다. 임의 계정/적/시간/승패/도주 목적지를 기본값으로 승인하지 않는다.
- 같은 권한으로 중복 Bind는 중복 등록하지 않는다. 다른 권한으로 교체하려면 명시적으로 Unbind한다. 도중 충돌 시 앞서 등록한 훈련 처리기를 되돌리고 기존 타 처리기는 보존한다. ServerManager 파괴 시 훈련 처리기도 해제한다.
- 상태/생성 목록은 배열을 복사하고 읽기 전용 값 스냅샷으로 공개한다. 잘못된 맵·좌표·세션/리비전·중복 ID·미초기화 상태를 거부한다. 알 수 없는 최대 AP를 공통20으로 대체하지 않으며 corpse와 HP를 강제로 일치시키지 않는다.
- **진입 UI/씬 로더·개체 생성기·전투 수신기에 새 패킷을 적용하는 작업은 아직 연결하지 않았다.** Bind API도 기존 모든 씬에 자동 실행하도록 설치하지 않았다. 전용 권한 구현과 함께 초기화 경로에서 호출해야 한다. 패킷 전송 성공은 클라이언트 상태 적용 성공이 아니다.

## 이번 검증

- Runtime/Editor/EditMode API 컴파일 오류0, Player Runtime API 컴파일 오류0. 기존 경고가 있으며 Unity Editor 임포트/실행과 다르다.
- 원작 전투 소스 오프라인573검사 통과. 새 훈련 패킷 검사40개를 포함하며 이전533개와 합산하지 않는다.
- 실제 컴파일한 NUnit 어셈블리의 관리 코드 검사 메서드1개를 직접 호출해 같은40검사를 통과했다. 별도40개로 합산하지 않으며 Unity TestRunner 실행이 아니다.
- ServerManager 컴포넌트의 실제 TryRequest/ResponseReceived·Unbind·기존 처리기 보존·알림 전달 NUnit 검사는 추가하고 컴파일했다. 실제 Unity 실행은 대기다.
- 기존 저장·계정·검증 XML은 변경하지 않았다. 이전247실패 전체 또는 실제 훈련장 플레이 통과를 주장하지 않는다.

근거 로그와 직접 호출 결과는 같은 폴더의 training-packets-* 파일을 따른다.

## 명명 변경

사용자 요청에 따라 훈련장 패킷 타입과 생성자를 `Request_EnterTraining` 형태로 통일했다. 요청은 Request_, 응답은 Response_, 서버 알림은 Notify_ 접두어를 사용한다. 처리기·테스트·위 표와 사용 예제를 함께 변경했다. Runtime/Editor/EditMode API 재컴파일 오류0. 이전 검증 로그·소스 해시는 당시 기록으로 보존하고 이번 컴파일은 `training-packets-rename-api.log`에 남겼다.

알림 접두어는 후속 사용자 지정에 따라 `Notify_`로 변경했다. 현재 이름은 `Notify_TrainingUnits`이며 사용처·생성자·테스트·문서를 함께 변경했다. Runtime/Editor/EditMode API 재컴파일 오류0 (`training-packets-notify-api.log`).
