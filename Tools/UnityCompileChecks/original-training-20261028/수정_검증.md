# 훈련장 원작 대조·수정

2026-10-28 KST. 기존 247개 실패 수정 작업을 보존한 상태에서 훈련장 관련 변경을 추가했다. 실제 Unity TestRunner·Play는 실행하지 않았다.

## 이번에 재확인한 원본

`Tools/MapChecks/inspect_training_original.py --late-dir <후기 Saver 폴더>`로 원본101set.arc~107set.arc의 디렉터리·범위·압축 항목 길이·체크섬을 검사했다. 초기판과 후기판7개 ARC는 바이트 단위로 동일하다.35개 원본 항목이 존재한다. 이전에 해제한 AI/EVT/DEE/DEO/SRF도 대조했다. 이번에는 DLL을 실행해 다시 압축 해제하지 않았으며, 기존 해제 자료와 원본 압축 파일 검사를 구분한다. 결과는 `Tools/MapChecks/original_training_check.json`.

- 각 맵 AI에는 인스턴스400·410의 ODNORMAL, ATTACK30/MAGIC30/REST40 비중이 있다. 이것만으로 몬스터 종류·총수·출현 위치를 정하지 않는다. AREA는 활동 영역이다.
- EVT 공통 `EVENT01 / INF / 1 TICK10 / REGEN2`. 반복 재등장 관련 자료는 존재하지만 TICK 단위·REGEN2 의미는 미확정이다. 102/105의 ENDDD를 원문대로 보존했다.
- DEE/DEO는 END와 ;999뿐이며 SRF는 ;999뿐이다. 이 항목들에는 초기 개체 생성 레코드가 없다. 다른 파일이나 서버 정보가 없다는 뜻은 아니다.
- 기존 네이티브 코드 분석의 dmSetChar/GetCharAbility/resetcharacter 경로와 HP/MP/XP 절대값·corpse/remove 독립 수신 근거는 `설계/09_전투_플로우_확인사항.md`의 원작 근거를 따른다. 이번 신규 실행에서 그 PE 경로 전체를 다시 에뮬레이션한 것은 아니다.

## 코드 변경

1. `OriginalTrainingMaps`는 정확한 원본 맵 씬명101~107만 식별한다. 직업별 배정·몬스터 편성은 제공하지 않는다.
2. `BattleMapPresentation.TryBind`가 성공한 원본 맵을 기준으로 지속 훈련 모드를 설정한다. 임시 적의 종류 일치나 Training{id}_Runtime 씬 동시 로드가 훈련장 식별 조건이 되지 않는다.
3. `BattleTransitionController`의 삭제된 World/TrainingRules 읽기·임시 적 기반 훈련 설정을 제거했다. `BattleSceneRoot.Training`에서 효과 없는 로컬 재등장 타이머 API도 제거했다. 로컬 시간으로 몬스터를 되살리지 않는다.
4. `TrainingEntrance2D`의 1단→101, 2단→102 식 추정 배정을 제거했다. 기존 메서드는 호환용으로false/0을 반환한다. 서버 맵 배정이 없을 때 임의 목적지로 보내지 않는다. 진입은 여전히 미완료이며 새 훈련장 서버 구현을 제공한 것은 아니다.
5. 테마 몬스터 생성기는 원작 복원 모드에서 실행 전에 거부한다. 기존 진단용 씬/에셋·원본 자료를 삭제하지 않았다. 기존 BattleEncounter2D도 복원 모드에서 비활성이다.
6. 전투 메뉴에서 로컬 자연 AP 회복이 진행된다는 문구를 제거했다. 메뉴 개폐가 HP/MP/AP·XP를 만들지 않는다.

지속 전투·도주까지 유지·시간 후 재등장은 사용자 확인 사항이다. 정확한 재등장 주기·출현 편성·도주 목적지/비용·사망 정책은 원본 서버 근거 없이 새로 만들지 않았다. 처치만으로 XP를 더하지 않으며 받은 경험치 절대값을 적용하는 기존 패킷 경로를 유지한다. 무료 회복·MP 전회복·자동 마을 복귀를 새로 추가하지 않았다.

## 검증

- Runtime/Editor/EditMode API 컴파일 오류0. Player Runtime API 컴파일 오류0. 기존 경고는 남음. 실제 Unity 임포트/실행 결과가 아니다.
- 연결된 프로덕션 전투 소스의 오프라인 검사533개 통과. 원본 훈련장 씬명/범위27검사를 포함하며 기존506검사와 합산하지 않는다.
- 테스트 어셈블리의 맵 식별 메서드 직접 호출14사례 통과. NUnit assertion을 실행했으나 Unity TestRunner는 아니다.
- 새 `OriginalTrainingTests`의 패킷·컴포넌트7사례는 소스/API 컴파일만 확인했다. 실제 실행 대기다. 사망 후 자동 종료/부활/로컬 보상이 없고 SetExp 중복 수신이 누적되지 않는지를 검사한다.
- 직업 배정에 관한 이전 싱글판 기대도 수정했다. ClassChangeExecutionTests의 전체 성공은 주장하지 않는다.
- 기존 검증 XML·계정/실패 저장은 변경하지 않았다. 기존247개 실패에 대한 실제 재검증 결과도 바꾸지 않았다.
