# 훈련장 중앙 진입·전투 옵션 도망·카오시아 복귀

2026-10-28 KST. 사용자 요청으로 훈련장 방문 경로를 로컬 서버 매니저에서 승인하도록 연결했다. 기존 247개 실패 수정 및 훈련장 패킷 정의 작업을 보존했다. 이번 기능은 사용자 승인 로컬 이동이며 원작 서버의 입장/도주 규칙을 복원했다는 뜻이 아니다.

## 구현된 흐름

1. 카오시아 기존 Training Entrance(8.5,23.5)의 트리거가 공통 `Request_EnterMap`을 보낸다. 기존 MapEnterRequest 이름을 Request_EnterMap으로 바꾸고 C# 사용처를 함께 변경했다. 건물과 훈련장은 하나의 맵 로딩 코루틴을 사용한다. 시나리오 입장 판정을 새로 구현한 것은 아니다.
2. ServerManager가 TrainingTravelService를 연결한다. 현재 Resource `World/TrainingTravel`의 대상은101번이다. 직업 단계로101~107을 자동 배정하지 않는다. 캐릭터 존재·문과의 거리·현재 맵·입력/전환 상태를 확인하고 세션ID와 중앙 타일(10,7)을 응답한다.
3. 맵20×15를 로드하고 중앙 통행을 확인한 뒤 기존 캐릭터만 훈련 그리드에 바인딩한다. 중앙 타일 중심은 Unity 좌표10.5,7.5다. 별도 몬스터·가짜 적·체험 능력치를 생성하지 않는다. 캐릭터 HP/MP/XP는 기존 세션에서 보존한다. 이동/전투/보상/재등장 규칙을 추가하지 않았다.
4. 로딩 완료는 Request_ReadyTraining으로 승인한다. 완료 전에는 원래 맵을 해제하지 않는다. 훈련 중에는 월드 이동 컨트롤러를 끄고 기존 전투 맵 UI에서 캐릭터 클릭→행동 메뉴→게임설정 또는 Esc로 전투 옵션을 연다.
5. 해당 전투 UI의 도망 버튼이 Request_RetreatTraining을 보낸다. 현재 훈련 UI와 세션을 소유한 코디네이터만 요청할 수 있다. 서버가 카오시아의 기존 FromTraining 타일8,21을 응답한다. 실제 Unity 위치는8.5,21.5로 입구에서 두 칸 아래다.
6. 카오시아 맵/런타임을 먼저 준비한 뒤 같은 Ready 요청으로 복귀를 확정한다. 성공 시 전투 UI/임시 방문 그리드를 해제하고 훈련 맵을 언로드하며 월드 입력·물리·카메라를 복원한다. 기존 SaveWorld로 복귀 상태 저장을 시도하고 저장 실패는 이동 성공과 별도로 기록한다.

입장·복귀 로딩 실패/거부 시 준비 중인 세션과 임시 UI를 되돌리고 원래 맵·위치를 보존한다. 중복·오래된 요청, 로딩 중 재요청을 거부한다. 건물과 훈련의 완료 응답을 구분해 이전 건물 응답이 훈련 이동 위치를 바꾸지 않도록 한다.

`Request_EnterTraining`은 기존 명시적 호출과 테스트용 계약으로 남아 있다. 실제 문 트리거는 공통 Request_EnterMap을 사용한다. Response_EnterTraining, Request_ReadyTraining, Request_RetreatTraining 등은 로컬 계약이며 새 원작 opcode를 만들지 않았다.

## 이번 실행 검증

- Runtime/Editor/EditMode API 컴파일 오류0, Player Runtime API 컴파일 오류0. 기존 경고는 남아 있다. Unity Editor 임포트/실행 결과가 아니다.
- 연결된 전투/프로토콜 오프라인604검사 통과. 새 방문 승인·중앙 좌표·준비 완료·실패 복구·도망·재진입31검사와 기존 패킷40검사를 포함한다. 이전573검사와 합산하지 않는다.
- 별도 오프라인 통합5,680검사 통과. 공통 진입 요청 타입 변경 후 기존 건물/계정/튜토리얼 등 연결 소스의 회귀다. 실제 씬 전환 검증이 아니다.
- 컴파일된 NUnit 어셈블리의 관리 메서드2개를 직접 호출해 방문31·패킷40검사를 통과했다. 위 오프라인 검사와 중복되므로 합산하지 않는다.
- UnityPy로 실제 자산을 읽어 Kaosia_Map / Town_Runtime / Map_101_; / Training101_Runtime 4개 씬이 모두 빌드 목록에서 활성임을 확인했다. Town_Runtime의 Training Entrance와 Spawn FromTraining 위치가 설정값과 일치한다. 입구 collider enabled/trigger도 확인했다.
- 101번 실제 맵에서 Ground 중앙(10,7)에 타일이 있으며 TerrainAttributes에는 해당 칸의 차단 타일이 없다. 카오시아 현재 Map.json의 입구(8,23)·복귀(8,21)도 속성0이다.
- 캐릭터만 있는20×15 그리드에서 기존 전투 옵션을 열고 상태를 유지하는 NUnit 소스를 추가하고 컴파일했다. Unity 네이티브 실행은 미실행이다.
- 실제 문 통과·옵션 클릭·왕복·카메라 육안·저장 재접속은 실행하지 않았다. 기존 저장·계정·검증 XML은 변경하지 않았다.

## 실제 Unity에서 확인할 순서

1. 별도 저장/신규 계정으로 튜토리얼을 마치고 카오시아에 도착한다. 기존 실패 저장은 덮어쓰지 않는다.
2. 기존 훈련장 문8.5,23.5에 실제 보행한다.101번 맵으로 전환되고 캐릭터가 중앙10.5,7.5에 나타나는지 확인한다. HP/MP/XP/골드/아이템이 바뀌면 실패다.
3. 임의 몬스터가 표시되거나 처치/보상이 발생하면 실패다. 이번 범위에는 전투·재등장이 없다. 이동 명령이 막힌 것은 아직 전투/이동 서버 판정을 추가하지 않았기 때문이다.
4. 캐릭터 클릭→게임설정 아이콘, 별도로 Esc를 사용해 전투 옵션을 연다. 메뉴 취소만으로 복귀하지 않는지 확인한다.
5. 도망을 클릭하면 카오시아8.5,21.5로 돌아와 입력·물리가 복원되고 훈련 맵/UI가 남지 않아야 한다. 카메라가 이전 맵에서 이동하는 장면이 노출되지 않는지도 확인한다.
6. 문에 다시 접근해 새 세션으로 재진입·재복귀한다. 중복 클릭·오래된 세션 요청·다른 UI의 도망이 현재 세션을 변경하면 실패다.
7. 격리 fixture에서 입장/복귀 목적지 로딩 실패와 거부를 발생시켜 원래 맵·좌표·입력·HP/MP/XP/돈 보존을 확인한다. 복귀 로딩 실패 후에는 다시 도망할 수 있어야 한다.
8. 복귀 저장 성공 및 Play 재시작 후 카오시아 위치 복원, 저장 실패 시 별도 메시지와 이동 완료 상태를 구분한다.

훈련장 내부 저장/중단 재개는 이번 기능에 추가하지 않았다. 기존 전투 중 저장 제한에 따라 훈련 방문 중 월드 저장은 거부되며, 정상 복귀 후 저장을 시도한다. 이 범위를 원작 전체 훈련장 완성으로 판정하지 않는다.
