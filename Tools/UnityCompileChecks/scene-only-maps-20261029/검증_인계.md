# 모든 맵 씬 저장·지형 JSON 의존성 제거 (2026-10-29 KST)

이 절은 이전 `non-scenario-tiles-20261029`의 ‘Map 데이터 보존/런타임 사용’ 설명을 대체한다. 원본 자료·현재 씬 자원·기존 상호작용 규칙을 기준으로 옮겼으며, 미확인 원작 서버 규칙은 추가하지 않았다.

## 최종 구성

- `Assets/_Game/Scenes/Maps`의156개 씬 모두 Ground 타일이 채워져 있다. 이미 저장돼 있던97개 바이너리 맵과 앞서 저장한51개 씬은 변경하지 않았다. 남아 있던 추가 전장33/330/331/332/333/404/405/406의8개 로더 전용 씬만 추가 배치했다.
- 새로 저장한 전체59개 씬의 바닥104754셀·장식6332개가 이전 변환 데이터와 일치한다. 원본 이미지·좌표·속성을 복사했으며 서버 입구/해금/보상/몬스터 판정을 추정하지 않았다.
- 지형 생성용파일52개와 해당.meta52개 삭제. 별도 이름의 런타임 지형 JSON으로 옮기지 않았다. 원본 그림/스프라이트·Tile 에셋·씬·원작 설치/분석 자료·계정/실패 저장은 보존했다.
- NativeTownScene은 씬의 Ground/Detail/TerrainAttributes와 지역 크기를 검증할 뿐 지형을 다시 생성하지 않는다. Geometry DTO·리소스 JSON 읽기·합성 바닥 Sprite 생성·지형 생성 fallback을 제거했다.
- 실내 NPC11명의 외형/픽셀 위치·프레임은 기존 `Town/OriginalInteriorStaff.json` 그대로다. 기존 가판대 접근 규칙으로 계산하던33개 허용 칸만 각 NPC의counterFrontCells로 옮겼다. 별도 NPC 구성 데이터이며 맵 전체 지형 데이터가 아니다. 맵을 생성하지 않고도 Runtime/NPC 씬을 구성할 수 있다.
- 이전 미사용 지형 데이터의npc/encounters를 근거로 임의 NPC나 필드 몬스터를 되살리지 않았다. 시나리오 Content/이벤트·패킷·NPC/입구 구성 JSON은 이번 삭제 대상이 아니다.

## 도구 변경

- 현재 도구: `bake_scene_tiles.py`, `check_scene_tiles.py`, `saved_scene_geometry.py`. 지형의 기준은 저장된 씬이다. 후자는 필요할 때 씬을 읽어 도구용 메모리 사전을 만들며 별도 지형 파일을 저장하지 않는다. 기존 도구의 읽기 경로도 씬으로 전환했다.
- 공용 에셋 폴더 `Art/Converted/NonScenarioMaps`는 참조 안정성을 위해 이름을 유지한다. 현재는 추가8개 전장에도 공유하며 바닥1425종·장식 이미지369종이다. 파일 이름이 적용 범위를 제한하지 않는다.
- 과거 resource/자동 배치 쓰기 도구8개(build_shop_interiors/build_world_fields/build_service_npcs/build_campaign_entrances/restore_kaosia/apply_safe_maps/migrate_world/build_new_scenarios)는 실행 시작 시 명확히 중지한다. 예전 초기 몬스터·한 명짜리 점원·문 좌표 정책을 재적용하거나 삭제한 파일을 되살리지 못하게 했다. 이전 구현은 Git 이력에 남는다.
- world_asset_baker의 이전 지형 생성과 로더 전용 씬 생성도 중지했다. JSON 출력 유틸은 폐기 파일 이름의 재생성을 거부한다. Unity의 기존 LegacyMapTilemapConverter/원본 MRC/GRS 분석기는 보존한다.
- 오프라인 실내 통행 검사는 SavedSceneTerrainReader로 실제 씬의 속성 Tile을 읽는다. 해당 .NET 어댑터는 YAML 전용이며 바이너리 씬 검증은 Unity나 Python 씬 리더를 사용한다. 실제 게임은 이 어댑터에 의존하지 않는다.
