# 원작 마을·필드 F키 재확인 (2026-10-29)

기존 튜토리얼/GameCtl F키 표는 전투용이다. 마을·필드용 기능으로 재사용하지 않는다. 이번에는 Saver1.2 실행 파일의 활성 화면 입력 전달, 별도 화면 키 분기, 창 생성 팩터리와 Wlib 원본 그림을 대조했다. 게임 코드는 수정하지 않았다.

## 코드 근거

- Saver.exe SHA256 `9b74f465f4a9c5ab3564fd1b47026aedf7c11e021f09dbf27be81fe47dd5c8f0`.
- `0x43B570`: 활성/모달 화면으로 가상 함수 +0x50을 통해 키 전달.
- 기본 화면 vtable `0x448534`, 파생 화면 vtable `0x44878C`의 +0x50은 모두 `0x42EEB0`.
- `0x42EEB0`: 실제 별도 키 분기. 키에서13을 뺀 뒤 `0x42F4BC`의 바이트 표와 `0x42F490`의 주소 표를 사용한다.
- 창 검색 `0x427270`은 가상 GetId 결과로 검색한다. 창 ID와 `sceneN.lsc` 번호는 다르다.
- 팩터리에서 ID18의 생성자 `0x41C0F0`은 scene2, ID67의 `0x41CE70`은 scene42, ID21의 `0x4126A0`은 scene6, ID20의 `0x41F570`은 scene4를 사용한다.
- ID19 생성자 `0x40FE20`은 필드+0xA8에19를 설정하며 scene3을 사용한다. ID33은 scene19/help.txt, ID27은 scene15, ID43은 scene27을 사용한다.
- `0x42F444`: 문자열 `0x450D20`=`/공간이동`을 +0xA0에 전달한다. 전투 F12 창과 다르다.

## 검증 및 한계

`python Tools/OriginalInputChecks/check_world_function_keys.py` 실행 통과: 원본 파일 해시,12개 키 점프 목적지,2개 공유 가상 함수 슬롯,레이아웃/명령 문자열을 확인했다. ASM 발췌와 원본 Wlib 배경 복원 그림을 같은 폴더에 보관했다. 그림은 정적 레이아웃이며 실행 캡처가 아니다. 원래 버튼/동적 이름·캐릭터는 이 배경 복원에 포함하지 않았다.

F6/F7/F10/F11의 ‘기본 분기’는 이 화면 처리기의 결과이며 전역·입력 포커스가 있는 자식 컨트롤까지 모든 기능이 없다는 증명은 아니다. 모달/포커스 상태에 따라 이 처리기까지 키가 도달하지 않을 수 있다. F12의 이동 목적지·서버 허용 조건은 확정하지 않았다.

후기 Saver.exe는 카탈로그에 SHA256 `dd512172256cf4795717aed156746fe6588b3434ed1e249ae59146e63d6e4689`로 기록되어 있지만 해당 해제 실행 파일은 현재 작업 경로에서 확보되지 않았다. 이번 고정 주소 결과를 후기 버전까지 동일하다고 확정하지 않는다. 원작 실행/Unity Play 검증은 수행하지 않았다.

## F2 하단 출전 토글 재확인 (2026-10-29)

사용자는 이 토글을 시나리오의 허용 캐릭터 수가2이상일 때 출전 여부를 설정하는 기능으로 확인했다. 원작 정적 분석에서 추가 캐릭터별 독립 플래그라는 구조는 일치한다. 다만 서버 코드/실행 패킷이 없어 인원 제한 적용과 실제 전투 생성 필터까지 독립 입증한 것은 아니다.

- 0x41C960은 보유 수가2이상이면 순번1부터 각 캐릭터 토글을 갱신한다. 순번0은 대상에서 제외하며 없는 칸은435590으로 비활성화한다. 여기서 검사하는 수는 보유 레코드 수이므로 이를 시나리오 허용 인원으로 명명하면 안 된다.
- 클릭0x41C330은 컨트롤 상태2이면 원시값1, 그 외에는2를 만들고 레코드+8(payload+4)에 기록한다. 선택 캐릭터 참조만 바꾸는0x41CA30과 별도 처리다.
- 0x41C9C0은42+캐릭터 레코드ID word+원시값 word를 전송한다.
- 원작 표시 방향의 추가 발견: 레코드값2는435570에0을, 값1은1을 전달한다.435570은 인수에1을 더해 컨트롤상태를 저장하므로 원시2→상태1(첫프레임), 원시1→상태2(두번째프레임)이다. 현재 Unity NativeCheckbox(value=raw==2)는 raw2에두번째프레임을 쓰므로 원본 프레임 매핑과 반대다. 이 분석 요청에서는 코드 수정하지 않았다.
- 따라서 이전 답변의 ‘2=체크/출전’은 원작 확인값이 아니다. 출전/비출전의 원시값 의미와 그림 프레임 매핑을 혼동하지 않는다. 사용자 기억은 출전 설정의 기능 근거로 기록하되 실제 선발/인원 제한 서버 동작의 바이너리 입증과 구분한다.

발췌 근거: saver12-world-roster-toggle.asm.txt. 실제 원작 또는 Unity 실행은 미수행.
