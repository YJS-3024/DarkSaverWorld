# 원작 재현 새 시작

이 폴더가 현재 Unity 작업 기준이다. 이전 게임의 코드·씬·프리팹·ScriptableObject·Resources와 임의 보완 데이터는 Assets에서 삭제했다. 기존 실행 게임이 유지되는 상태가 아니다.

현재 실행 흐름은 **로컬 프로필 → 최초 지휘관 생성 → 대기실/전투 튜토리얼 → 카오시아**다. `Scenes/Start.unity`를 열어 Play한다. 로그인/서버 선택 UI와 요청은 보존되어 있으며 `EntrySceneRoot`의 사용 설정을 켰을 때만 거친다. 최초 생성은 파이터/나이트/매지션3카드이며 기존 캐릭터를 재생성하지 않는다. 미완료 튜토리얼은 재접속하면 처음부터 시작한다.

카오시아/실내·수련장·필드/시나리오 이동과 시설·전투·성장 수신 경로가 추가되어 있다. 이는 모든 원작 서버 규칙이나 실제 Unity Play 검증의 완료를 뜻하지 않는다. 연결은 확보한 원본 근거 또는 사용자가 저장한 입구/진입점 설정을 사용한다. 최신 구현 범위와 검증 한계는 `설계/10_분석_적용_진행표.md`, `설계/테스트_검증_계획.md`의 최신 절을 따른다.

| 폴더 | 내용 |
| --- | --- |
| SourceData | 후기 원본 데이터의 바이트 복사본, 엄격한 CP949→UTF-8 텍스트, 원본 파일/지도 목록 |
| Data | 원문 호환 CSV, SET/POS 배치 참조와 진입/튜토리얼/월드·시설 실행용 에셋·근거 |
| Art | 원본 그림과 별도 진입/튜토리얼/월드·시설 파생 그림. 변환 근거·검정 색상키를 별도 기록 |
| Audio | 원본 MIDI/WAV는 SourceData/Native에 보존. 튜토리얼 악보의 별도 합성Ogg는 Art/Tutorial에 명시적으로 연결 |
| Runtime | 새 진입 클라이언트·Unity UI·로컬 서버/계정 저장. 기존 런타임은 이식하지 않음 |
| Editor | 시작 씬 설정·로컬 계정/성장 관리·시나리오/입구 편집·원작 전투 패킷 검사 |
| Scenes | 원본 진입 UI와 로컬 서버를 연결한 Start |
| Tests | 새 구현의 검증 위치. 이전 검사를 새 구현의 통과 결과로 사용하지 않음 |

`SourceIndex.json`은 자료별 출처·SHA256·변환 증거다. 원본 데이터를 남겼다는 사실과 모든 필드/분기/서버 동작의 의미가 확정됐다는 주장은 다르다. 미확정 값·누락 자산은 그대로 구분하고 몬스터·보상·시간·공식을 추측해 채우지 않는다.

원본 좌표는 원본 좌표로 저장한다. Unity 좌표 변환은 이후 표시 계층에서 처리한다. 원문 CHARPOS·AI AREA·SOILDER를 전체 초기 편성으로 바꾸지 않는다. CSV 능력치를 서버 최종 수치라고 가정하지 않는다. 원작과 사용자 지정 로컬 서버 정책은 별도 파일/이름으로 구분한다.

Unity에서 `Scenes/Start.unity`를 연다. **DarkSaver → 새 시작 → 기반 설정**은 진입 컴포넌트/아트 참조를 포함해 씬을 다시 만들고 빌드 씬을 하나로 설정하며 이전 preloaded assets를 비운다. 씬을 직접 편집했다면 이 메뉴의 재생성이 그 씬을 교체한다는 점을 확인한다. Canvas는 Play 때 Unity UI로 구성한다.

재구현 순서는 시작/가입/로그인/서버 선택 → 캐릭터 생성/튜토리얼 → 카오시아/실내 → 수련장 → 필드/시나리오다. 통신 형태는 요청→로컬 서버 매니저→응답→표시로 다시 구성한다. 프로토콜 근거가 없는 로컬 계약을 원작 opcode로 표시하지 않는다.

과거 구현 전용 `Tools`의 생성기/검사기는 이전 Assets 경로·타입·씬을 전제로 하므로 그대로 실행하지 않는다. 현재 `_Original` 검사 실행은 `Tools/run_original_checks.py`로 환경 경로를 명시한다. 원본 분석의 기준 문서는 저장소의 `설계/11_후기버전_분석기준.md`, `설계/원작_튜토리얼_분석.md` 등 기존 분석 문서다. 과거 구현/통과 기록은 현재 상태가 아니다.

삭제 전 실제 작업 파일은 Assets 밖의 로컬 백업에 보존했다. 위치·범위·검증 결과는 `Tools/OriginalRestart/reset-report.json`을 따른다. 이 백업은 Git으로 공유되지 않는다. 계정·저장본·원본 설치파일·분석 폴더는 삭제하지 않았다.

## 원작 전투 패킷 검사

Play 중 **DarkSaver → 로컬 서버 → 원작 전투 패킷 검사**를 연다.50/51 초기 편성은 여러 줄,31 처치 병종 목록·53 경험치 setter·54 결과표·60 팀 이름은 한 줄의 완전한16진수 메시지로 입력한다. 미리보기만으로는 저장하지 않으며 별도 검증 프로필에서 명시 적용한다. 현재 캐릭터/맵 접속·생명·revision을 사용하는 로컬 봉투는 원작 프레이밍이 아니다. 수치·편성·보상은 자동 생성하지 않는다.

54는 결과표 표시만 담당한다. 명시적인 클리어/종료 승인 전에54만으로 전투가 끝나거나 돈/XP/아이템이 지급되지 않는다. 결과 수신/확인은 저장될 수 있다. 원본 실행 코드 대조·관리형 검사와 실제 Unity Play/Editor 조작은 구분한다. 재검증 순서는 테스트 계획의2026-11-05 저녁 절을 따른다.

## 일반 맵 귀환 입구

시나리오 편집툴의 입구 연결에서 일반 마을/필드/실내의 이동 입구를 선택하면 도착 맵의 귀환 연결을 확인할 수 있다. **귀환 입구 초안 만들기**는 양쪽 맵과 영역을 맞바꾼 별도 입구를 미사용 상태로 만든다. 위치·크기·기존 입구 겹침을 확인한 뒤 사용을 켜고 저장한다. 플레이 중의 자동 역방향 연결 생성 기능이 아니며, 시나리오 결과/수련장 도망은 기존 전용 경로를 쓴다. 새 설정은 Play를 다시 시작해 읽고 별도 프로필로 검증한다.

처치 목록31은 별도 표시 데이터다. 결과표 전에는 현재 시나리오 세션에 보관하고 결과표에 결합해 저장한다. 사망/제거 알림이나54에서 목록을 임의 만들지 않으며, 경험치/돈/아이템 지급에도 사용하지 않는다. 결과 후31 저장 실패는 기존 목록을 유지하고 재시도할 수 있다. 실제 재검증은 테스트 계획의2026-11-05 밤31 절을 따른다.
