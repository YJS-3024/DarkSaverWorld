# 새 런타임

전투 원본 메시지50/51은 `NativeUnitSnapshots`의 WORD/DWORD/길이 문자열 디코더와 공통 수신기를 통해 반영한다. `Notify_BattleUnitPackets`/`Notify_TrainingUnitPackets`는 최초 편성을 한 번에 검증·저장하는 로컬 봉투이며, 이후 단일 메시지도 `Notify_BattlePacket`으로 전달할 수 있다. 전투용 수신 레벨/이름/HP·MP/XP/마법·기술 슬롯은 별도 `nativeInfo`로 보존한다. 축약50의 누락값을 계정의 실제0으로 덮지 않고51의 표시 레벨을 베이스/클래스 레벨로 추정하지 않는다. 원작 서버의 편성값·전체 송신 순서·미확정 시전 비용은 포함하지 않는다.

60 팀 이름 표도 공통 원본 수신기로 전달한다. 알림 봉투의 `expectedTeamRevision`은 현재 `WorldView.battleTeamRevision`이며 원본 바이트에 붙이지 않는다. 개체 수신 전에도 받을 수 있고 전투창은 앞9행의 첫 일치 팀 이름을 우선한다. 계정 이름/소유 편성/자원/진행 중 요청은 변경하지 않는다. 접속·맵 문맥을 벗어나면 표시 표를 폐기하고 재수신하며 계정 파일에 저장하지 않는다.

Editor의 로컬 서버 메뉴에 `원작 전투 패킷 검사`가 있다.50/51 개체 메시지 묶음 또는53/60 단일 메시지의16진수를 미리 해독하고, 명시 버튼으로 현재 Play 수신기에 전달한다. 개체/XP 수신은 저장할 수 있으므로 별도 검증 프로필을 사용한다. 스탯·편성을 자동 생성하지 않는다. 최초 지휘관의 HP/MP가 미확정이면 축약50으로 계정 MP0을 만들지 않고 상세51을 기다린다. 개체 갱신의 원본 마법 슬롯 초기화는 승인된 대상에만 적용한다.

기존 게임 로직은 남기지 않았다. Entry의 기본 흐름은 시작→별도 로컬 프로필→최초 지휘관 생성이다. 로그인·서버 선택 화면/요청/처리는 보존하지만 기본 경로에서 사용하지 않는다. Play 전에 EntrySceneRoot의 Use Login And Server Selection을 켜면 기존 계정 방식으로 돌아간다. 로컬 프로필은 OriginalLocalServer/local-profile-v1.json,기존 로그인 계정은 accounts-v1.json으로 분리한다.

Tutorial은 Saver.exe의1500 대기실 수업과 tutorial.arc의301 전투 수업을 순서대로 실행한다. 선행 수업 완료 전에는 전투 시작 요청을 거부한다. 미완료 재접속은1500부터 재시작하며,양쪽 수업을 끝낸 뒤 완료 상태만 저장한다. 기존 로컬 프로필이 있으면 그 캐릭터를 복원하며 로그인 계정을 자동 선택하거나 이전 저장을 이관하지 않는다.

화면/입력은 확인한 원작 근거를 따르고 LocalEntryPolicy/계정 파일 처리는 로컬 호스팅 정책으로 분리한다. 원작 wire opcode/서버 초기 수치·영구 실습 아이템 보상은 추측해 넣지 않는다. 원본 확인 범위·표시 환산·직접 검증은 설계/원작_튜토리얼_분석.md와 설계/테스트_검증_계획.md를 따른다.

World는 WorldEntryReady를 받아 카오시아21,21로 진입한다. 사용자 확인을 따른43×43 외부 지도와 후기 실내10종을 원본 타일·장식으로 표시하며,출입구·격자 보행·직원 클릭·시설 창을 LocalServerManager의 Request_/Notify_ 계약에 연결했다. 지도는 Start씬의 uGUI 실행기가 데이터로 구성한다. 별도 맵씬/Unity Tilemap을 생성한 것은 아니다. 외부 문과 실내의 연결 좌표·역할은 명시적인 로컬 설정이며 원작 서버의 좌표 복구로 취급하지 않는다.

무기·방어구·소모품·마법사의 집·장신구점의 현재 재고는 `Data/World/KaosiaWorld.json`의 shops를 따른다. 현재5목록에85품목이 등록돼 있으며 원본 안내표 근거와 사용자 선택 정책을 원작 전체 재고와 구분한다. 용병 후보는 현재 기술·장비를 원본 고용 테이블에 적용해 계산한다. 성장정보 미수신 계정에는 기술을 소급 지급하지 않는다. 초기 자금·수수료·부활 비용·고용 승인·매입가 등 미확정 운영값을0으로 확정하지 않으며 관련 요청은 명시 응답을 필요로 한다.

신전은 유령의 부활과 생존자의 성향 변경 요청을 분리한다. 성향 변경은 원본scene29 그림·버튼과AC 금액DWORD 송신을 연결했다. 명시 견적이 없으면 대기하며 Esc/우클릭으로 닫을 수 있다. 견적 공급/성향 승인 정책 자체가 기본 구현된 것은 아니다.

수련장101~107은 로컬 직업 단수1~7에 따라 같은 마을문에서 각각 진입한다. 원본 서버의 단수별 라우팅 공식으로 주장하지 않는다. 초기 전투 정보가 없으면 마을식 걷기를 차단하고 `Notify_TrainingInitialRequested` 응답을 기다린다. 명시 유닛 정보 수신 후 전투 명령을 처리한다. 기본 로컬 테스트 공급기는 저장된101/102 편집 배치와 원본 능력치표를 사용하며, 이 공급기가 없거나 해당 배치가 없으면 초기 응답을 계속 기다린다. 도망과 수련장 내부 종료 후 재접속은 원래 마을 수련장문으로 복귀한다. 관리형 검증과 실제 Unity Play를 구분한다.

편집기 메뉴 DarkSaver → 원작 도구 → 시나리오 편집툴은151개 선택 지도의 전투 배치 편집/연출 위치 참고·아군/상자/이벤트 좌표 표시를 지원한다. 코드는 Editor/Scenario에만 있으며 사용자 배치는 Editor/ScenarioLayouts에 저장한다. 원본 데이터와 게임 저장은 수정하지 않는다. 수련장101~107의 사용자 배치 저장은 Player용 TrainingTestLayouts와 참조 카탈로그에도 내보내며 다음 로컬 테스트 입장에 반영한다. 시나리오 배치 저장은 별도 초기 전투 응답을 대신하지 않는다. 사용법과 원본 근거 경계는 Tools/ScenarioPlacementChecks/README.md를 따른다.

필드·시나리오 클라이언트 추가 후에는 NativeCampaignArt/CampaignCatalog가 원본 월드 맵29개와 시나리오97개를 제공한다. 마을/실내·수련장17개와 합쳐143개 지도 리소스를 지원한다. Runtime/Maps의 공유 MRC/GRS 해독기를 편집기와 게임에서 함께 쓰며 현재 맵의 바닥·장식·몸체를 분리해 표시한다. 대형 필드도 타일마다 버튼을 만들지 않고 하나의 격자 입력면을 사용한다. 원본에서 미확정인 연결 좌표는 자동 생성하지 않는다. 현재 사용자가 저장한22개 입구 설정을 로컬 서버에서 사용하며, 실제 연결 대상·좌표는 UserGateways.json을 따른다.

편집툴의151지도와 런타임143지도의 차이는 편집 전용 대련장201~207과 튜토리얼301이다. 편집툴은 마을/실내·필드·수련장도 함께 표시한다. 원본 전투 배치는5슬롯 묶음으로 테두리/색상을 표시하며, 저장된 사용자 배치와 원본/실제 스폰을 구분한다.

확인된16맵/610개 전투 개체는 원본 SET/POS 위치로 표시·점유 처리한다.97개 시나리오 중 도입 대본이 있는52개는 대사/배치/방향/이동/대기/지도 리소스 전환 상태를 처리한다. Request_EnterMap은 근거 있는 연결/현재 위치/저장 성공이 필요하다. 원본 연결이 없으면 거부한다. Request_ClearScenario와 전투 결과/보상 자동 생성은 보류한다. 별도의 신뢰된 로컬 서버 어댑터가 Receive_ScenarioClear로 현재 맵/세션/중복 방지 알림을 제공할 때만 원본 종료 대본을 시작한다. 종료 대본의 FIRSTCLEAR/GETGENERAL 등 서버 의존 명령도 자동 판단/지급하지 않고 보류한다. intro/explore/outro/complete는 로컬 표시 복원 상태이며 전체 시나리오 처치 기록/능력치/보상 저장 구현을 뜻하지 않는다. 개발 결과는 Tools/OriginalWorldChecks/campaign-check.json,직접 검증은 설계/테스트_검증_계획.md 첫 절을 따른다.

후속 사용자 기억의 ‘시나리오 입구마다 NPC1명’을 별도 사용자 설정으로 지원한다. 편집툴의 NPC 입구 연결에서 외형·출발 타일·대상 시나리오·도착 타일을 직접 정하고 Data/Campaign/UserGateways.json에 저장한다. 원본은 변경하지 않는다. 신규 설정의 기본은 비어 있고 적용도 꺼져 있지만 현재 사용자가 저장한 설정은 켜져 있다. 각 연결 사용과 전역 로컬 서버 사용을 켜서 저장한 경우에만 다음 진입에 NPC가1명 생성된다. 타일을 밟아 자동 입장하지 않으며 근처에서 클릭→원본 Wlib11 틀의 로컬 방1개 선택→참가를 거쳐 Request_JoinScenarioRoom이 위치/시설 토큰/저장 성공을 검사한다. 이는 원작 서버의 전체 방 생성/매칭 정책 재현이 아니며 기존 전투/보상 보류도 해제하지 않는다. 현재 편집기에는 카오시아 구버전43×43과 실내도 포함해151맵을 표시한다.

Editor의 DarkSaver → 로컬 서버 → 성장·전직 테스트는 명시 테스트용 경험치 지급/직업 변경 기능이다. 실제 운영 전직 정책을 대신하지 않는다. 계정 관리의 캐릭터 초기화는 Play 종료 후 대상 캐릭터만 제거하고 계정 인증정보·다른 계정을 유지하며 원시 저장을 먼저 백업한다. 기존 실패 저장에 자동 실행하지 않는다.

구버전 지도 선택은 Tools/OriginalWorldChecks/select_legacy_maps.py와legacy-map-selection.json을 따른다. 1001·1002·1004·1008·1009·1010·1011·1012·1030·1060·1110·1111은 보존된1.2 MRC/GRS를 함께 사용한다. 1001은43×43,1002는40×40이다. 나머지 비교 가능한 지도는 현재 구버전과 같거나 이미 구버전이며,구버전 자료10지도와필수GRS가없는29번은후기참조를유지한다. 사용자출입구/시나리오편성/NPC·기존저장은변경하거나좌표이관하지않는다. 크기가달라진지도의사용자좌표는편집툴에서해당버전으로재검토해야한다.

전투 배치 탭의 사용자 지휘관 진입점은 UserGateways.json의 선택적entryPoints에 별도 저장한다. 맵/해시·좌표·사용 여부를 명시하며 기존 자료가 없으면 기본 진입 규칙을 유지한다. 사용자 진입점은 연결 전역 applyToGame과 별개로 해당 점 enabled에 따라 사용한다. 시나리오/수련장 실제 입장 요청에서만 기존 도착 좌표보다 우선하고 출발/클리어 복귀 위치는 유지한다. 저장 위치·원본 POS·명시 전투 유닛 응답을 이동시키지 않는다. 시나리오 배치 저장은 스폰 응답을 대신하지 않으며 수련장 테스트용 내보내기와 구분한다.

사용자 입구를 적용할 때 캠페인의 전체 그림/음향 IsConfigured를 총괄 조건으로 사용하지 않는다. 월드/로컬 서버 시작은 설정 Merge를 실행하며 카탈로그·입구 파일 연결 누락은 명시 실패한다. 현재사용자커밋5e59d9a6의입구22개가활성상태이며카오시아는기존수련장문을포함해14입구다. 실제실행시Console의「로컬 입구 설정」로그로사용여부/적용수를확인한다. 설정파일/배치101·102/기존계정은자동수정하지않는다.


수련장 로컬 전투의 기본 스탯은 `units_all.csv`에서 변환한 `OriginalCombat.json` version4를 사용한다. 캐릭터·몬스터·보유 용병에 동일한 생성 경로를 사용하며 저장된 HP/MP·최종 스탯이 있으면 이를 보존한다. 임시 능력치1/10은 제거했다. 원본 미사용값 -1은 baseStats에 보존하고 MP/마공 전투값에는0을 쓴다. AP20·인접 공격 주기와30초 리스폰은 별도 로컬 정책이다. 기본 공격/반격의 고정 피해1은 제거했고 현재 유효 공격력−대상 유효 방어력(0 하한)을 공통으로 적용한다. 받은 유효 스탯을 우선하며 누락/무효는1로 대체하지 않는다. 여러 몬스터 반격은 각각 별도 승인 통지를 사용한다. 원작 서버의 레벨/장비/피해 공식을 복원한 결과가 아니다. 배치 JSON은 `TrainingTestLayoutCatalog.asset`의 명시 참조로 Player에 포함하고, 성장·전직 Editor 창에서 실제 전투 스냅샷을 비교할 수 있다.

수련장 지휘관/보유 용병의 기본 공격 처치에는 원본 `획득경`을 현재 지휘관에게 직접 지급한다. 사망과 XP를 같은 응답/저장으로 확정하며 리스폰한 새 생명의 재처치는 다시 지급한다. 레벨 보정·분배·자동 레벨업과 금전/아이템 보상은 추가하지 않았다. 신규 레벨1 성장 기록이 없을 때0XP로 준비하고 기존 기록은 보존한다.

수련장 후속 연결: 원본 피격 숫자/공격/사망 소비 이벤트와 마지막 방향, AP5C04(사용자 지정 최대20·초당2), 용병 AI의 확인된 제어 전이/복귀를 사용한다. 활성 요청 중 AP 갱신과 세션 교체 콜백을 보호한다. Editor의 수동 회복은 버튼을 눌렀을 때만 저장하며 신전 정책과 별개다. 편집툴 진입점은 공통/직업 전용을 구분하고 기존 공통 JSON은 호환된다. 수련장 단수는 원본 직업 설명의 stage를 사용하며8~10단 방은 임의 생성하지 않는다. 병종에 맞는 지형이 전혀 없는 경우 편집툴이 알리며 자동 좌표/지형 보정은 하지 않는다. 상세 검증 경계는 설계/테스트_검증_계획.md의 최신 절을 따른다.

맵/전투 응답의 후속 알림은 현재 캐릭터·접속·맵·전투 revision을 확인한다. 첫 알림의 콜백에서 로그아웃·재입장·새 전투 상태 수신이 일어나면 이전 후속 알림을 전달하지 않는다. 성장·전직 테스트 창의 원표 요구 경험치는 참고 표시이며 자동 레벨업 기준을 확정한 값이 아니다.

수련장 게임용 배치는 맵 번호·격자 크기·유닛 범위/중복을 검사한다. JSON 파싱·맵/중복/범위 검사 실패는 경고 후 초기 응답 대기를 유지하며 성장 저장이나 전투를 생성하지 않는다. 편집 파일은 저장됐지만 게임용 파일/임포트/참조 저장이 실패하면 원래 편집 파일과 저장 해시를 보존하고 다시 저장할 수 있게 표시한다. 새로고침만 실패한 경우에는 저장 성공과 경고를 구분한다.

전투 상태창에서 선택한 용병/몬스터의 병종명은 전체 원본 전투 카탈로그에서 조회한다. 플레이어 성장 목록에 없다는 이유로 비우지 않으며 서버 사용자 이름/별칭/레벨은 임의 생성하지 않는다.

원작5C53은 받은 개체의 절대XP를 교체한다. 지휘관은 성장/전투 XP를 한 저장으로 반영하고 다른 개체는 자신의 XP만 보관한다. 전달 문맥의 생명·전투 revision과 지휘관 성장 revision으로 오래된 값을 거부한다. 받은 같은 직업 레벨 증가는 전투 유닛과 원자 반영하며 HP/MP가 없으면 회복하지 않는다. 승인된 XP/레벨 갱신은 진행 중인 전투 이동을 유지한다. 경험치 차감/누적에 따른 자동 레벨 계산은 선택하지 않았으며 Editor의 두 계산 결과는 읽기 전용이다.

원작5C64/65는 개체 시점을 맞춘 뒤 명시 적대 목록에서4001의mode1 요청을 준비한다. `Notify_BattleFocusRequested`는 불변 생명/접속/현재 격자 문맥이며 월드 표시기가 시점에 반영한다. 이동의 승인된 목적지와 보간 픽셀 위치를 현재 격자 칸으로 혼동하지 않는다. `Notify_BattlePacketRequested`는 원작 요청 바이트를 로컬/외부 권위자에 전달하는 경계다. 이 제어 통지만으로 연출/피해/비용/XP/레벨을 적용하거나 저장/행동 취소를 하지 않는다. 대상 없음은 시점만, 음수 개체는 무시하며 오래된 콜백의 후속 발송을 차단한다. 자동 처치→레벨 임계치 판정→64/65 생성 순서를 추정해 연결한 것은 아니다.

게임용 배치 내보내기도 기존 원자 파일 저장기를 사용하며 편집 파일과 내용 해시가 같아야 한다. 참조 카탈로그의 배열 길이/중복 맵 번호가 잘못되면 기존 배열을 보존하고 저장을 거부한다.
