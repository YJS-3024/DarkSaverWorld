# DarkSaver 재구축 기반

현재 실행 구조는 **클라이언트 요청 → ServerManager의 로컬 서버 처리 → 응답 수신 → 화면 갱신**이다. 하나의 Unity 앱 안에서 동작하고 외부 접속은 하지 않는다. 전투·시나리오01~17·맵/이동·캐릭터 선택/생성·주요 마을/세션 작업을 이 경계로 연결했다. 신규 기능도 표시/UI에서 판정하지 말고 등록된 로컬 처리기에서 검증한 뒤 응답을 보내도록 작성한다.

`Network/LocalServerDispatcher`는 요청 타입당 하나의 처리기를 소유하며, `ServerManager.TryRequest`는 명시적인 승인/거절을 반환한다. `LocalScenarioServer`는 원본 스크립트 실행 상태를 소유하고 Director에는 복사된 응답을 보낸다. 확인된 공격/마법 요청 및 공격 연출/HP/MP 응답은 원본 프레임으로 인코딩·디코딩하며, 미확정 기능은 로컬 전용 메시지로 구분한다. 전체 원작 프로토콜이나 서버 공식 복원은 아니다. 통신 기록은 `LocalServer.CaptureTrace()`, 검증 범위는 진행표의 **ServerManager의 로컬 서버 요청·응답 구조** 절을 따른다.


기존 프로토타입을 제거하고 정적 분석 결과를 기준으로 새로 구성한 첫 실행 단위다.

- `Runtime/Maps`: 원본 MRC 크기 공식과 타일 속성·가림 비트 파서
- `Runtime/Events`: 명령별 좌표 순서를 보존하는 EVT 파서
- `Runtime/Combat`: 원작의 요청/선행 연출/서버 결과 적용 경계를 싱글게임용으로 분리
- `Runtime/Rendering`: 캐릭터·전경 스프라이트·상태 UI 패스 순서와 물 오버레이 규칙
- 원본 MRC/ARC/ATR는 분석 폴더에 보관하고 에디터에서 Unity 자산으로 변환한다. 런타임에서 원본 파일을 직접 읽지 않는다.

현재 전투 공식은 서버 실행 파일 부재로 임시 로컬 판정기를 사용한다. 데이터·상태 전이 경계는 원작 분석 결과를 따른다.

현재 진행·검증 범위는 `설계/10_분석_적용_진행표.md`를 따른다. 맵 씬의 존재는 시나리오 이벤트·몬스터 편성의 플레이 완료를 의미하지 않는다.

시나리오01은 `Scenes/Entry/Start.unity`에서 캐릭터 슬롯 선택/생성 후 최초 튜토리얼을 마치고 카오시아의 `시나리오1 입장`으로 진행한다. 대사는 다음 버튼 또는 Space/Enter로 넘기며, 보스 전투 결과 확인·복귀 후 완료 연출과 자동 저장이 이어진다. `Runtime/Events/Scenario01Controller.cs`와 순수 규칙 모델이 기존 부트스트랩·전투·저장에 연결된다. 원본 초기 편성이 없는 부분은 보완33유닛/3단계/기존 개별 조우 정책을 사용한다. 세부 연출의 원작 일치와 실제 Unity Play는 별도 검증 범위다.

시나리오01의 대사 초상과 열린 상자7개는 원본 이미지로 연결했다. `Visuals.json`은 진행 저장 해시를 바꾸지 않는 별도 표시 바인딩이다. 원본에 정의가 없는 MAGIC1은 다른 마법으로 대체하지 않는다. 원작 창 테두리·전체 재생 타이밍과 실제 Unity Play 검증은 남아 있다.

시작 흐름은 **최초: 시작 → 최초 로그인 → 캐릭터 선택/생성 → 튜토리얼 → 카오시아(21,21)**, **이후: 시작 → 로그인 → 마지막 캐릭터의 이전 종료 위치**다. 로그인/캐릭터 선택은 ServerManager의 로컬 요청·응답으로 처리한다. 마지막 캐릭터 경로를 별도 기록하고 실제 위치·진행은 해당 저장 파일에서 복원한다. 캐릭터10슬롯과 손상/백업 저장의 덮어쓰기 차단을 유지한다. 튜토리얼 단계도 저장하며 완료한 튜토리얼은 반복하지 않는다. 정상 종료·일시중지·맵 도착 때 위치를 저장하고, 전투 중 종료는 전투 진입 전의 월드 체크포인트에서 이어간다. 실제 Unity Play 검증은 남아 있다.

카오시아의 **마을 시설 → 시나리오1 의뢰**에서 케인·타란의 원본 대사를 읽고 수락할 수 있다. 시나리오1에서 해당 목표를 달성한 뒤 마을에서 보고하면 원본 결과에 따른 보상(20,000골드 / 팔찌)을 한 번 지급하고 자동 저장한다. 의뢰 접근 UI는 싱글판용이며 원본 NPC 좌표는 아직 배치하지 않았다. 상점은 사용자가 확인한1~3단 클래스용 무기·방어구 범위를 바탕으로, 원본 표에서 요구 레벨0~30·유료·착용 가능한202종을 재구성한다. 개별202종 모두가 원작 판매 품목으로 확정된 것은 아니다. 구매가는 표 가격을 사용하며, 미확정인 매입가는 비활성화한다. 최신 대조 결과는 Tools/MapChecks/town_bindings_check.json을 따른다.

네 마을 **카오시아·벨퓌어스·시시리오·캐슬림**은 이제 필드 출입구로 왕복한다. 마을 이동 메뉴는 제거했다. 가까운 **노란 출입 표식**에 목적지 이름이 표시되며, 표식을 밟으면 다음 지역으로 이동한다. 도착점은 복귀 출입구와 떨어져 있어 이동 루프를 방지한다.

일반 월드용 원본 지형18개와 마을4개를 연결했다. 기존1010 외17필드에 Map/Runtime 씬34개·원본 지형/장식·68개 기본 수치 조우·지역 저장/불러오기를 추가했다. 실제 지형은 Play/로드 시 구축한다. 필드별 별칭·지역 연결·몬스터 편성/좌표는 싱글판 구성이고 원작 서버 표 복원이 아니다. 시나리오/던전 내부는 별도다. 바닥은 원본 첫 프레임이며 전체 타일 애니메이션 재생은 아직 포함하지 않는다. 필드 조우는 같은 방문에서 처치 후 비활성화하고 지역이 다시 로드되면 재등장한다.

변환/검사는 Tools/MapChecks/{build_four_towns.py,build_world_fields.py,check_four_towns.py,check_world_fields.py}를 사용한다. 지역 배치·경로는 Resources/World/Routes.json, 대조 결과는 Tools/MapChecks/world_fields_check.json을 따른다. 위치·진행은 기존 캐릭터 슬롯에 저장한다.

시나리오 **01~17**은 원본 맵 씬+각 Runtime 씬의 공통 실행기로 연결했다. 필드의 시나리오 표식을 밟아 진입하고,02부터는 이전 시나리오 완료 후 입장한다. 진입 연출→보완 몬스터 조우/원본 이벤트→완료 연출→보상·진행 저장→필드 복귀 흐름이다.02~17은975유닛의 싱글판 보완 배치를 쓰며 원작 서버 초기 편성이 아니다. 완료한02~17은 중복 보상 방지를 위해 재입장을 막는다.01의 기존 입장 UI도 유지한다.

추가 진행은 저장v4에 보존하며 기존01/구버전 저장을 유지한다.02·08·12의 A/B 완료 원문은 모두 포함하되 선택 기준이 없어 기본A를 사용한다. 지휘관 획득은 해금 기록이며 추가 지휘관 조작/편성은 미구현이다. 미확정 사인/CHARPOS2 조건·FX1 상세 효과·누락 MIDI(nco02)는 임의 복원하지 않았다. 현재 클라우드에서 실제 Unity Play는 검증하지 못했다. 실행/변환/검사 범위는 진행표의 **시나리오01~17** 절과 `Tools/MapChecks/campaign_resource_check.json`을 따른다.

로그인 화면의 **회원가입**에서 아이디·비밀번호·확인을 입력해 이 기기의 계정 하나를 등록할 수 있다. 가입 후에는 해당 계정으로 인증하고 캐릭터10슬롯/저장 위치를 계속 사용한다. 계정이 없는 기존 플레이는 ‘계정 없이 로그인’을 유지한다. 비밀번호 입력은 마스킹하며 파일에는 PBKDF2 해시·소금만 보관한다. 외부 서버의 회원가입이나 다중 계정 저장 분리는 포함하지 않는다. 현재 검증 범위는 진행표의 **회원가입 페이지·로컬 계정 인증** 절을 따른다.

캐릭터 선택은 사용자 정정을 반영해 **10칸(2열×5행)**으로 구성했다. 처음3개의 저장 경로는 유지하고4~10번 파일을 추가한다. 원작에서3칸이 확인된 것이 아니며, 원본 선택 화면의10칸을 별도로 실행 검증했다는 뜻도 아니다.

원본 실내 **22종**을 `Resources/Interiors/원본번호`의 바닥·장식·충돌 자료와 `Scenes/Maps/Interior번호_Map`, `Scenes/Runtime/Interior번호_Runtime` 씬으로 구성했다. 개별 확인은 `Scenes/Entry/Interior번호_Play.unity`를 열어 Play하면 GameCore와 해당 두 씬을 로드하고 통행 가능한 시작점에 배치하도록 했다. 지형은 씬 로드 시 생성되며 에디터 계층에 미리 직렬화한 전체 타일맵은 아니다. 실제 Unity Play 검증은 미완료다.

포함 번호는1500·2000·2010·2100·2110·2120·2130·2140·2150·2160·2170·2180·2190·2200·2300·2400·2510·2600·2700·2800·2900·3000이다. 무기점·방어구점·용병상점·장신구점·소모품점·은행·창고와 교회/주점형 및 역할 미확정 실내가 포함된다. 간판/그림으로 확인된 용도와 실제 시설 기능 구현을 구분한다. 별도 NPC·재고·은행/교회 서비스는 이번 맵 구성에 추가하지 않았다.

카오시아 **무기점·방어구점 문 앞 출입 표식**을 밟으면 원본2000·2100 실내로 진입한다. 기존 별칭 씬 이름과 저장 경로는 유지한다. 카운터 접근 또는 ‘상점 이용’으로 기존 구매 화면을 열며 무기112종·방어구90종으로 나뉜다. 하단 출구로 건물 앞에 복귀하고 실내 위치도 저장·재로그인 시 복원한다. 카오시아와2000/2100의 대응·문 임계점·카운터 상호작용 위치는 싱글판 선택이며 원본 서버 연결표 복원은 아니다. 추가로 장신구점2200·은행2400·창고2510·신전2600·마법도구/소모품점2300을 카오시아에 연결했다. 문 앞 출입 표식→실내→하단 출구→해당 건물 앞으로 왕복하며 위치 저장/재로그인 복원을 지원한다. 은행/창고는 같은 외관 두 건물에 역할을 부여한 싱글판 선택이다. 이번 추가 연결은 출입/저장이며 각 시설의 신규 구매·예금·보관·신전 서비스는 포함하지 않는다. 나머지 실내는 독립 진입 씬으로 제공한다. Play 미리보기 종료는 에디터 Play를 중지한다.

생성/검사는 `Tools/MapChecks/{build_shop_interiors.py,check_shop_interiors.py}`를 따른다. 원본 첫 프레임의 바닥/보조 타일·장식 픽셀, 장식 순서·좌표, 지형 속성을 보존한다. 전체 타일 애니메이션·원작 서버 전송/NPC 배치는 별도다.

사용자 지정으로 카오시아 연결 실내7곳에 NPC를 한 명씩 배치했다. 이름은 무기점 주인·방어구점 주인·장신구점 주인·마법도구점 주인·은행 직원·창고 직원·신전 관리인이다. 원본 마을사람 외형809/810/805/816/807/827/817의 정지 프레임을 사용하며 검정 배경은 투명 처리했다. 외형 배정·역할 이름·좌표는 싱글판 설정이다. 무기점/방어구점 NPC 접근과 상점 이용 버튼은 기존 구매 UI를 연다. 다른5곳은 NPC/이름 표시만 추가했으며 신규 시설 서비스·대사는 포함하지 않는다. 같은 원본 실내의 독립 Play 씬에도 같은 NPC가 표시된다. 앞선 NPC 미배치 기록은 이 변경으로 갱신한다.

네 상점(무기·방어구·장신구·마법도구/소모품) NPC를4타일 거리 안에서 클릭하면 이동을 멈추고 각 구매 UI를 연다. NPC 몸체를 클릭할 수 있게 트리거 범위를 확장했다. 기존 상점 이용 버튼/접근도 유지한다. 장신구는 원본 장착위6, 마법도구/소모품은7 중 요구 레벨0~30·양수 가격 항목으로 싱글판 재고를 구성한다. 원작 상점별 재고표를 복구했다는 뜻은 아니다. 구매는 기존 로컬 요청·응답/인벤토리·금액 처리를 사용하고 매입은 비활성화한다. 네 상점의 저장 문맥과 시설별 품목 제한을 함께 적용했다.

지역 오디오는 `WorldAudioService`가 자동으로 생성되어 마을·필드·실내의 원본 맵 번호를 `Resources/World/Audio/Manifest.json`과 연결한다.44개 번호 중40개는 원본 BGM 대응표이며1111→1110,1410→1400,1500→2000,2510→2500의4개 계승은 싱글판 보완이다. 동일 음악의 지역 이동에서는 재시작을 피하고, 시나리오 Runtime이 활성화되면 지역 BGM을 멈춰 기존 연출 음악에 넘긴다. 종료 후 지역 음악으로 복귀한다. 필요한 AudioListener를 유지하며 지역 음악은2D 반복 재생이다.

원본 MIDI는 FluidSynth/TimGM으로 Ogg 변환했으므로 당시 Windows 신디사이저 음색을 보장하지 않는다. 원본 WAV20개는22,050Hz 모노8비트→16비트의 정확한 샘플 변환으로 포함했다. 기존 전투 마법 효과음, 지원되는 시나리오 마법의 시작/도달·정지 효과음과 사망 효과음1을 연결했다. 사망은 현재 전투 표시 상태 전환을 사용하며 원본 표시ID700~799 제외를 반영한다. 공격·발걸음·상점·UI는 원본 재생 ID/조건을 확인하지 못한 곳에 임의 소리를 붙이지 않았다. 누락된 원본 시나리오곡 nco02는 대체하지 않으며 이전 곡이 잘못 남지 않도록 정지한다. PLAYMIDI 생략 모드1·명시 모드를 유지한다.

생성/검사는 `Tools/MapChecks/{build_world_audio.py,check_world_audio.py}`다.44개 바인딩·13개 고유 BGM 클립·WAV20개610,887샘플의 원본 대조를 통과했다. 실제 Unity 재생/청음과 지역/연출 전환 타이밍 검증은 미완료다.

원본 마법표439항목의 처리 경로를 연결했다. 전투용은 마법/아이템 효과289개·특수기85개이며 현재 캐릭터의 ‘마법/특수기’ 메뉴에서 습득·선택된 기술만 사용한다. 대상/부대/방향을 지정하면 기존 로컬 요청·응답으로 효과와 비용을 처리한다. HP/MP 흡수·재생·부활·약화/강화·독/수면/침묵·면역·각종 공격 특수기를 포함한다. 레벨업의 원본 추가 습득 행도 반영하며 선택8칸은 자동 교체하지 않는다.

고용50개는 기존 ‘마을 시설→용병’ 경로를 사용한다. 감정표현15개는 월드의 ‘감정표현’ 버튼에서 선택하며 로컬 승인 후 원본 FX3 애니메이션을 캐릭터 위에 표시한다. 감정표현은 AP/MP를 소비하지 않는다. 미확정 서버 판정은 싱글판 수식·지속 시간·AP 정책으로 구현했으며 원작과 동일한 공식이라는 뜻은 아니다. 상세는 설계09의 최신 전체 마법·특수기 절, 실행/자산 검사 결과는 `Tools/MapChecks/all_abilities*_check.json`을 따른다. 실제 Unity에서 전 직업의 클릭·연출·밸런스를 확인하는 검증은 아직 남아 있다.
